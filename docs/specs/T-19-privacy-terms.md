## 概要
Google の OAuth を本番の公開ステータスにすると（T-12 決定事項7。仕様書PR「Google の OAuth を本番に」）、同意画面に、自分のドメインのプライバシー ポリシーと利用規約の URL を入れることになる。そこで、`https://kokohima.app/privacy` と `https://kokohima.app/terms` を、ログインしなくても読める画面として `apps/web` に作る。本文は、アプリが実際に保存するもの・外に渡すものから作り、この仕様書の「6.」「7.」に文案として全文を置く。

> **注意**：「6.」「7.」の文案は、法律の助言ではない。仕様書と実装から作った下書きで、最終の文言は利用者が決める（「確認事項」）。

## 振る舞い

### 1. 経路と描画
- 経路は `/privacy`（プライバシー ポリシー）と `/terms`（利用規約）。
- 本番では、`not_found_handling: single-page-application`（T-12）で `index.html` が返るので、直接開いても、再読み込みしても画面が出る。wrangler の設定は変えない。
- `apps/web/src/App.tsx` で、ログインの状態を見る前に描画する（今の `/invite` と同じ位置）。ログインの確認中（`checking`）、API に届かない（`error`）、ログインしていない（`anonymous`）のどれでも、ログインの画面に移さず本文を出す。
- 画面は `apps/web/src/pages/PrivacyPage.tsx` と `TermsPage.tsx`。本文は JSX のテキストで書く（`dangerouslySetInnerHTML` や Markdown の変換は使わない。CSP と XSS の対策のまま）。
- 遅延読み込み（`React.lazy`）にはしない。本文は短い文字列で、初回の読み込みへの影響が小さいため（必要なら実装PRでビルドの大きさを見て決め、仕様書を直す）。
- 本文は API を呼ばない。外のオリジンのものを読まない（画像・フォント・埋め込みなし）。

- 節の見出しは `h2`、その中の見出しは `h3`。本文の色は `text-ink`、制定日・注記は `text-ink-muted`、リンクは `text-action underline`。色・余白・角丸は `apps/web/src/index.css` のトークンを使う（T-11）。

### 4. リンクの置き場所
- **ログインの画面**（`apps/web/src/pages/LoginPage.tsx`）：ボタンの下に、`text-s text-ink-muted` の1行で次を置く。
  - 「ログインすると、利用規約とプライバシー ポリシーに同意したことになります。」（「利用規約」「プライバシー ポリシー」をリンクにする。同意の取り方は「確認事項」）

# プライバシー ポリシー

制定日：2026年◯月◯日

ここ暇 運営（以下「運営」）は、Web アプリ「ここ暇」（以下「このサービス」）で預かる個人情報を、次のとおり扱います。

## 1. 運営者と連絡先
- 運営者：ここ暇 運営
- 連絡先：ops@kokohima.app
- 運営者の氏名と住所は、個人情報保護法にもとづいて求められたときに、遅滞なくお知らせします。

## 2. 預かる情報

### ログインで受け取るもの
- Google アカウントの識別子（Google がアカウントごとに発行する番号）
- Google で確認済みのメールアドレス（お知らせのメールの宛先にだけ使います）
- Google アカウントの名前・プロフィール写真・パスワードは受け取りません。

### あなたが入力するもの
- 表示名と、用意した中から選んだアイコン
- ここ暇（誘っていい時間の範囲）、くり返し、時間帯プリセット
- 友達ごとの「見せる／見せない」の設定
- 誘い・募集の内容（相手、日時、エリア、ひとこと、リンク）、返事、成立した予定
- 友達の関係と、発行した招待リンク（リンクの鍵は、元に戻せない形でだけ保存します）

### カレンダーを連携した人から受け取るもの
- Google カレンダーの、空き／埋まりの時刻だけ。予定のタイトル・場所・参加者・説明は、取得も保存もしません。
- Google から受け取る許可（更新用のトークン）。暗号化して保存します。
- このサービスがあなたの Google カレンダーに作った「ここ暇」カレンダーの識別子

### 通知のためのもの
- お知らせ（アプリの中で読む通知）と、通知の設定
- プッシュ通知の宛先（ブラウザが発行する URL）。暗号化して保存します。

### 使うときに自動で生まれるもの
- ログインの記録：ログインした時刻、最後に使った時刻、ブラウザ名と OS 名の要約（例：「Safari / iOS」）。ブラウザが送る情報（User-Agent）の全文と IP アドレスは保存しません。
- IP アドレス：短い時間に同じ操作がくり返されていないかの判定にだけ使い、保存しません。
- 動作の記録（ログ）：障害や不正に気づくための記録です。利用者を区別する番号が入ることがありますが、メールアドレス・名前・ひとこと・トークン・カレンダーの認証情報は入れません。

## 3. 使う目的
1. ログインと、本人の確認のため
2. 友達どうしで「ここ暇」を見せ合い、誘い・募集・返事をやりとりするため
3. 成立した予定を、連携したカレンダーに書き込み、カレンダーのファイル（.ics）で渡すため
4. 連携したカレンダーに予定が入ったとき、重なる「ここ暇」を自動で取り消し、空いている時間を候補として出すため
5. 誘い・予定・友達の追加などを、お知らせ・プッシュ通知・メールで知らせるため。新しい端末でのログインを、メールで知らせるため
6. 誘い・募集に付けたリンクの、タイトルと画像のプレビューを作るため
7. 不正な利用を防ぎ、障害に気づいて直すため
8. この規約・ポリシーの大事な変更を知らせ、問い合わせに答えるため

このサービスは、広告を出しません。預かった情報を売りません。アクセス解析のツールも使いません。

## 4. ほかの利用者に見えるもの
- 友達には、あなたの表示名・アイコンと、「見せる」にした友達にだけ「ここ暇」（時刻の範囲だけ）が見えます。「見せない」にした友達には、暇がないときと同じに見えます。
- 誘い・募集の相手には、送った内容（日時・エリア・ひとこと・リンク）と返事が見えます。募集に応じた人の名前は、募集した人が「決める」まで、誰にも見せません。
- 招待リンクを開いた人には、リンクを発行した人の表示名とアイコンが見えます。
- 予定が成立すると、Google カレンダーを連携している参加者の「ここ暇」カレンダーに、ほかの参加者の表示名・日時・エリアを書き込みます。.ics のファイルにも同じ内容が入ります。書き込んだ予定は、その参加者の Google アカウントの中にあります。終わった予定は消さないので、あとから運営が消すことはできません。
- 退会すると、相手の履歴には「退会したユーザー」と出ます。

## 5. 外部の事業者に任せること（委託）
このサービスは、次の事業者に、必要な範囲で情報の取り扱いを任せています。

### Cloudflare, Inc.（米国）
- 任せること：サーバー、データベース、ファイルの保管、処理の待ち行列、ログ、ドメイン
- 渡すもの：このサービスのすべての情報

### Google LLC（米国）
- 任せること：ログインと、カレンダーの連携
- 渡すもの：ログインの手続き。連携した人のカレンダーへの、空き／埋まりの問い合わせ。成立した予定の書き込み（ほかの参加者の表示名、日時、エリア、アプリと誘いのリンク。ひとことは書きません）

### Resend（米国の事業者。メールは東京の拠点から送ります）
- 任せること：メールの配信
- 渡すもの：メールアドレス、件名、お知らせの種類の短い説明。新しい端末でのログインのときは、ブラウザ名と OS 名の要約と、ログインの日時。誰から何が届いたかの中身は渡しません。

### ブラウザのプッシュ通知の事業者（Google・Apple・Mozilla・Microsoft）
- 任せること：プッシュ通知の配信
- 渡すもの：通知の宛先と、中身のない合図だけ。誰から何が届いたかは渡しません。

### リンクのプレビューを作るとき
- 誘い・募集にリンクを付けると、運営のサーバーがそのページを読みに行きます。相手のサイトからは運営のサーバーのアクセスに見え、あなたの IP アドレスや Cookie は渡しません。
- ページの住所を調べるのに、Cloudflare の DNS（cloudflare-dns.com）を使います。
- 画像は運営のサーバーから配るので、友達の端末が相手のサイトにつながることはありません。

## 6. 第三者への提供
- 本人の同意なく、個人情報を第三者に提供しません。ただし、法令にもとづく場合（裁判所や警察などから、法令にもとづく求めがあったときなど）は除きます。
- 「5.」の委託は、第三者への提供にあたりません。運営は、委託先の取り扱いを、契約と設定を通して確かめます。

## 7. 外国での取り扱い
- 「5.」の事業者は米国の事業者です。情報は、日本の外（米国や、Cloudflare の世界各地の拠点）で保管・処理されることがあります。
- 米国には、日本の個人情報保護法にあたる、国全体の包括的な法律はありません（分野ごとの法律や州の法律があります）。各国の制度は、個人情報保護委員会の「外国における個人情報の保護に関する制度等の調査」で確かめられます。

## 8. 保存する期間
- アカウント（メールアドレス・表示名・アイコン・Google の識別子）、友達、設定、くり返し、カレンダーの連携：退会したときに消します。
- ここ暇の枠：始まってから2日で消します。
- 誘い・募集・成立した予定：予定の時間が終わってから30日で消します。
- お知らせ：作ってから30日で消します。
- 招待リンク：期限から30日で消します。
- ログインの記録：使えなくなってから30日で消します。新しい端末でのログインに気づくため、最初のログインの記録だけは退会まで残します。
- プッシュ通知の宛先：ログアウトしたとき、届けられなくなったとき、ログインが切れたとき、退会したときに消します。
- カレンダーの空き／埋まりの記録：連携を解除したとき、30日アプリを開かなかったとき、退会したときに消します。
- リンクのプレビュー：使う誘い・募集がなくなり、取ってから30日を過ぎたら消します。
- ログ：7日で消えます。
- データベースの復元用の記録：消したあとも、最大30日は復元のための記録に残ります。
- 外部の事業者（「5.」）が持つ記録（メールの送信の記録など）は、それぞれの事業者の定めによります。

### 退会したとき
- 退会すると、すぐに消します（取り消しはできません）。相手の履歴を「退会したユーザー」と出すため、利用者を区別する番号と退会した時刻だけは残します。
- あなたの Google カレンダーの「ここ暇」カレンダーを消し、Google の許可を取り消します。
- これからの成立した予定は、「やっぱり難しい」を押したのと同じになります。

## 9. 安全のための取り組み
- 組織：運営が、個人情報の扱いに責任を持ちます。漏えいやそのおそれがあれば、影響を調べ、法令に従って個人情報保護委員会への報告と、本人への通知を行います。
- 人：運営に関わる人は、本番の情報を、必要な作業のときだけ扱います。
- 物理：情報は Cloudflare のデータセンターにあります。運営は、自分でサーバーを持ちません。
- 技術：
  - 通信はすべて暗号化（HTTPS）します。
  - カレンダーの許可とプッシュ通知の宛先は暗号化して、ログインと招待リンクの鍵は元に戻せない形で保存します。
  - 情報を読む処理では、友達の関係と「見せる／見せない」を必ず確かめます。
  - ログに、個人情報やトークンを出しません。
  - 運営のアカウントは、パスキーなどの多要素認証で守ります。
  - 使っているソフトウェアを更新し続け、異常を監視します。
- 外国の環境：「7.」のとおりです。

## 10. Cookie と、端末に置くもの
- ログインを続けるための Cookie と、ログインや招待の途中で使う短い Cookie（長くて1時間）だけを使います。

## 確認事項（合意前に解消する）
1. **文言**：「6.」「7.」の文案は法律の助言ではない。利用者が全文を読み、最終の文言を決める。必要なら専門家に見てもらう。
2. **制定日**：「2026年◯月◯日」を、デプロイの日に合わせて利用者が決める（決めるまで `deploy:prod` が止まる）。
3. **裁判所**：運営者の住所を書かないので「日本の裁判所で解決します」にした。「運営者の住所地を管轄する裁判所」などにするかは、利用者が決める（消費者の利用者には、住所地から遠い専属の管轄は認められないことがある）。
4. **運営者の氏名と住所**：個人情報保護法では、運営者の氏名（名称）と住所を、本人が知りうる状態（求めに応じて遅滞なく答える形を含む）に置くことになっている。「求められたときに、遅滞なくお知らせします」で足りるか、利用者が確かめる。
5. **同意の取り方**：ログインの画面の「ログインすると、利用規約とプライバシー ポリシーに同意したことになります。」で同意とみなす形にした。チェックボックスなどにするか。すでにログインしている友達への知らせ方（初回のデプロイのときに、メールで知らせるかなど）。
6. **大事な変更の知らせ方**：アプリの画面で全員に知らせる仕組みがない（#91）。当面は、運営が全員にメールを送るか、ほかの方法にするか。
7. **Resend**：送信の拠点が東京であること（利用者から聞いた値。リポジトリの仕様書には書かれていない）、事業者の正式な名称と国、送信の記録の保存期間（#89）を、Resend の管理画面と規約で確かめる。
8. **D1 の復元の記録**：Time Travel で、消した行が最大30日復元できる（#89 の記載）。本番の D1 での実際の期間を確かめる。
9. **外国の制度の書き方**：「7.」の米国の制度の説明と、個人情報保護委員会の資料の名前・リンクを、公式の資料で確かめる（この作業環境からは読んでいない）。リンクを付けるなら URL を決める。
10. **Google の限定使用の文**：「11.」は Google API サービスのユーザーデータに関するポリシーの、限定使用の開示の文を日本語にしたもの。公式の英語の文と見比べる（審査のときは英語の文が求められることがある）。
11. **`profile` のスコープ**：T-12 の人が行う作業3は、同意画面のスコープに `profile` を入れているが、ログインの要求は `scope=openid email`（T-01）で、名前と写真は受け取らない。同意画面から `profile` を外すか、本文に「同意画面には出るが受け取らない」と書くか。
12. **アイコン**：「用意した中から選んだアイコン」は T-15（下書き）の形。T-15 より前にこのページを出すなら、今は `avatar_url` が常に NULL なので、この行を外すか、そのまま出すか。
13. **JavaScript なしの表示**：SPA なので、JavaScript を読まない取得（Google の確認の仕組みなど）には本文が見えない。審査で困るなら、静的な HTML の版を別のタスクで作る。
