## 概要
今は、Google カレンダーを連携している人の成立した予定が、裏で自動で「ここ暇」カレンダーに書き込まれる（T-06）。持ち主から「勝手に追加するのではなく、追加するかを選べる方がいい」と要望があった。
成立した予定の画面に「カレンダーに追加」を置き、押すとその場で「Googleカレンダーに追加」と、端末のカレンダーに追加（iPhone なら「iPhoneのカレンダーに追加」）が開くようにして、押した予定だけを本人が入れるようにする。「Googleカレンダーに追加」は、日時・場所などを入れた状態の Google カレンダーの追加画面を開くだけで、保存するかは本人が Google の画面で決める。アプリからの自動の書き込みはやめ、Google への書き込みの許可（`calendar.app.created`）も新しくは求めない。

## 前提
- 連携（`calendar.freebusy`）は、空きの候補（T-06・T-55）と自動取り消しのために残す。連携は「空きを読む」ためだけのものになる。
- 「Googleカレンダーに追加」は、アプリのサーバーから Google を呼ばない。画面が予定の内容から Google カレンダーの追加画面の URL（`https://calendar.google.com/calendar/render?action=TEMPLATE&...`）を作り、本人が押したときに開く。連携していない人も使える。
- そのため、アプリは「Google に入れたか」を知らない。予定がキャンセルされても、本人が Google に保存した予定はアプリからは消せない（.ics と同じ。決めたこと3）。
- Google Cloud の同意画面に登録しているスコープから `calendar.app.created` を外すのは人の作業（Google の審査 #199 と一緒に行う）。実装PRのマージとデプロイの後に行う。
- Apple カレンダー（T-09。未着手）も、自動で書かない方針にそろえる。Apple の人は今までどおり .ics で入れる。

## 振る舞い

### 1. 予定の画面の欄
- 成立した予定の詳細と、成立の演出の中（T-43）の `MeetupCalendarActions` を、「カレンダーに追加」のボタン1つにする。連携の状態は読まない（`GET /calendar/connections` を呼ばない）。
- 「カレンダーに追加」（副のボタン。カレンダーのアイコンと、右に開閉の向きの印）を押すと、ボタンのすぐ下に2つの選択肢がその場で開く（決めたこと2）。シートは重ねない。
  1. 「Googleカレンダーに追加」（リンク。新しいタブで開く。右に外へ出る印）
  2. 端末のカレンダーに追加（`IcsButton`。押したときの動きは今のまま）。名前は端末で変える（決めたこと4）。画面に「.ics」と書かない。
     | 端末 | ボタンの名前 | 押すと |
     | --- | --- | --- |
     | iPhone | 「iPhoneのカレンダーに追加」 | 標準のカレンダーへの追加画面が開く |
     | iPad（`Macintosh` と名乗り、タッチ点が2以上のものも含む） | 「iPadのカレンダーに追加」 | 同じ |
     | Mac | 「Macのカレンダーに追加」 | ファイルを保存し、開くとカレンダーに入る |
     | それ以外（Android・Windows など） | 「ほかのカレンダーに追加」 | ファイルを保存する |
     - 判定は `navigator.userAgent` と `navigator.maxTouchPoints` で、画面を開いたときに1回だけ行う（`apps/web/src/calendar/` の純粋な関数。単体テストで表のとおりか確かめる）。判定を外しても、押したときの動きは同じ（名前が違うだけ）。
- 開閉は `apps/web/src/ui/Collapse.tsx`（T-56「0-4.」）で動かす。ボタンに `aria-expanded` と `aria-controls`。もう一度押すと閉じる。選択肢を押しても閉じない（.ics の失敗の文言を選択肢の下に出すため）。最初は閉じている。開いた・閉じたは覚えない（画面を開き直すと閉じている）。
- 選択肢は、ボタンと同じ枠の中の沈んだ面（`surface-sunken`）に、区切り線（`line`）で並べる。どれも高さ44px以上。主のボタン（`primary`）にはしない。「入れなくてもよい」ことを見た目で押しつけないため。
- 「キャンセル」は置かない（もう一度押すと閉じるため）。
- 出す条件：予定が `confirmed` で、終了が画面を開いた時刻より後のときだけ。キャンセル・終わった予定では、どちらも出さない（今の .ics は終わった予定でも出ているが、そろえる）。
- 選択肢の下の静かな1行（`Note`）：「押した予定だけが入ります」。開いているときだけ出す。連携・自動の話はしない。

### 2. Googleカレンダーの追加画面の URL（`googleCalendarAddUrl`）
- `packages/shared`（`calendarAdd.ts`）に純粋な関数として置く。入力は予定（`Meetup`）とアプリの origin。予定の参加者は、閲覧者自身と抜けた人を除いた形で `GET /meetups/{id}` から届くので、そのまま使う（閲覧者の ID は要らない）。
- 中身は、T-06「書く内容」と同じ（タイトル・日時・場所・説明）。ひとことは入れない。
  - `text`：「ここ暇：<自分以外の抜けていない参加者の表示名を「、」でつなぐ>」。いなければ「ここ暇」。表示名がない人は「名前未設定の友達」、退会した人は「退会したユーザー」。
  - `dates`：`<開始>/<終了>`。どちらも UTC の `YYYYMMDDTHHMMSSZ`。
  - `location`：エリア（なければ付けない）。
  - `details`：`<origin>/meetups/<id>` と、誘いのリンク（あれば）を改行でつなぐ。
- 値はすべて `encodeURIComponent` で符号化する（利用者が入れた文字で別の引数を作れない。`packages/shared` は DOM の型を持たないので `URLSearchParams` は使わない）。
- 表示名の決め方（「名前未設定の友達」「退会したユーザー」）・タイトル・説明の組み立ては、api の `eventContent.ts`（.ics）と同じ関数と定数を `packages/shared` から使い、2か所でずれないようにする。
- リンクは `target="_blank"`・`rel="noopener noreferrer"`。スマホでは、Google カレンダーのアプリかブラウザの追加画面が開く。Google にログインしていなければ、Google のログインを経て追加画面になる。

### 3. 連携の画面（`/settings/calendar`）と文言
- Apple の行の「Appleカレンダーは準備中です。成立した予定は .ics で追加できます」を、「Appleカレンダーとの連携は準備中です。成立した予定は、予定の画面の「カレンダーに追加」から入れられます」にする。
- 「読むのは空き／埋まりだけで、予定のタイトル・場所・参加者は読みません。成立した予定は「ここ暇」カレンダーに書き込みます。」を、「読むのは空き／埋まりだけで、予定のタイトル・場所・参加者は読みません。成立した予定は、予定の画面から自分で追加できます。」にする。
- 予定の画面に戻ってきたときの帯 `?calendar=connected` の文言（「連携しました。Googleカレンダーの『ここ暇』に入ります」）は、予定の画面から連携を始めなくなるので使わない。T-57 の戻り先の処理は残し、帯の文言を「連携しました」にする。

### 4. 自動の書き込みをやめる（consumer）
- `MeetupConfirmed`・`CalendarConnected` では、Google に書かない。
- `MeetupCancelled`・`MeetupLeft` では、`calendar_id` を持つ連携（前に「ここ暇」カレンダーを作った人）について、その予定を消すことだけを続ける（決めたこと3）。予定のIDは T-06 の決まり（`kh` ＋ UUID）なので、書いていない予定を消しても404で成功として扱われる。
  - 消すときは、前に書いたタイトル（抜けた人を除いた名前）の書き直しもしない。
- `calendar_id` が NULL の連携では、何もしない。カレンダーを作らない。
- 「ここ暇」カレンダーの作り直しはしない。消すときの404・410は成功として扱う（予定もカレンダーもないときを区別できないので `calendar_id` は残す）。上限以外の403なら成功として扱い、`calendar_id` を NULL にする。上限の403は一時的な失敗（Queue の再試行）。
- 退会（T-16）の「ここ暇」カレンダーを消す段は今のまま（`calendar_id` があるときだけ）。
- outbox の型と Cron は変えない（`MeetupConfirmed` などは通知にも使う）。

### 5. スコープ
- 新しい連携・連携し直しで求めるスコープは `calendar.freebusy` だけ。
- 前に `calendar.app.created` も許可した人のトークンは、そのまま使う（連携し直しを求めない）。

### 6. プライバシー ポリシーと利用規約（T-19。本文は実装PRで合わせ、改定日はマージしてデプロイする日。予告は付けない）

- 「4.」の書き込みの項：「『Googleカレンダーに追加』を押すと、ほかの参加者の表示名・日時・エリア・アプリと誘いのリンクを入れた Google カレンダーの追加の画面を開きます。保存するかはあなたが Google の画面で決めます。保存した予定はあなたの Google アカウントの中にあり、運営は消せません。.ics も同じです」。

## 認可と秘匿
- 閲覧者IDの使い方：追加画面の URL は、閲覧者が読める `GET /api/v1/meetups/{id}`（参加者だけ。T-04）の応答からだけ作る。新しく読むデータはない。
- 他人のデータに届かないことの保証：新しい API がない。参加者でない予定は今までどおり404で、欄は出ない。
- 区別させない応答：変えない。
- Google に渡る内容：本人が押したときだけ、本人のブラウザから、本人がすでに画面で見ている内容（表示名・日時・エリア・リンク）が Google に渡る。ひとことは入れない。サーバーのログには何も出ない。
- 予定の中身を Google から読まないことは変わらない。スコープが減るので、書ける範囲は狭くなる。

## 決めたこと
1. 「Googleカレンダーに追加」を押したあと：(a) 日時と場所を入れた Google カレンダーの追加画面を開き、本人が Google で保存する／(b) 今の連携のまま、押した予定だけアプリが書く。**(a) に決まった**（持ち主の判断）。書き込みの許可が要らなくなり、連携していない人も1回押すだけで入れられる。
2. 並べ方：(a) 2つのボタンを最初から並べる／(b) 「カレンダーに追加」1つを押すと、Google・.ics・キャンセルの選択肢のシートが下から出る（Google マップの形）／(b') 「カレンダーに追加」1つを押すと、すぐ下にその場で選択肢が開く。**(b') に決まった**（持ち主の判断。モック https://claude.ai/artifact/Tvrn9AYtPQUfqUp8JmLGNV の「案B'」）。ボタン1つで画面がすっきりし、予定の詳細（それ自体がシート）の上にシートを重ねずに済む。
3. 前に「ここ暇」カレンダーに書いた予定：(a) キャンセル・抜けたときに消すことだけ続ける／(b) 何もしない（キャンセルされても残る）／(c) デプロイのときに「ここ暇」カレンダーごと消す。**(a) にした**（推奨のとおり）。(b) は、キャンセルされた予定が Google に残り、本人が行くつもりで来てしまうおそれがある。(c) は、本人が見ている予定が断りなく消える。

4. .ics のボタンの名前：(a) 端末で変える（「iPhoneのカレンダーに追加」など）／(b) どの端末でも「ほかのカレンダーに追加」／(c) 今のまま「ほかのカレンダーに追加（.ics）」。**(a) にした**（推奨のとおり）。「.ics」はファイルの形式の名前で、押すと何が起きるかが伝わらない。iPhone の人には、自分のカレンダーに入ることがそのまま伝わる。
