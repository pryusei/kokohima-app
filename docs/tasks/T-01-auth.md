# T-01 認証（Google／Sign in with Apple、セッション）

## 目的
利用者がGoogleまたはAppleでログインし、再読み込みしてもログイン状態が続くようにする。以降のすべてのAPIが「誰が見ているか」を安全に受け取れる土台を作る。

## 関係する要件
- F-01：認証（GoogleとSign in with Apple。メールログインはなし）
- NF-04：認証情報の暗号化
- セキュリティ設計「認証とセッション」

## スコープ
- やること：
  - Google／AppleのOAuth（OpenID Connect）ログイン。state・nonce・PKCEを使う
  - IDトークンの署名・発行者・宛先・nonceの検証
  - ユーザーの作成（初回）と、プロバイダIDとの対応づけ
  - アクセストークン（JWT、10〜15分）の発行。クライアントはメモリにのみ保持
  - 更新用トークンの発行・ローテーション・再利用検知（HttpOnly・Secure・SameSite Cookie、D1にはハッシュのみ）
  - 更新用エンドポイントのOrigin検査
  - 認証済みの閲覧者IDをapplication層に渡すミドルウェア
  - ログアウトと全端末ログアウト
  - E2E用のテスト用ログイン（`POST /__e2e__/login`）と、本番に含めないための安全策（`e2e-testing` スキル参照）
  - Playwrightの初期設定（setupプロジェクト、ユーザーA・B・Cの認証状態）
- やらないこと：
  - アカウント連携（GoogleとAppleの統合）は別タスク
  - 新端末ログインのメール通知は、通知タスクで実装する（ここではイベントを出すだけ）
  - カレンダーの許可（ログインとは分ける）

## 受け入れ条件
- [ ] Googleでログインすると、初回はユーザーが作成され、2回目は同じユーザーになる
- [ ] Appleでも同様に動く
- [ ] state・nonceが一致しない、署名が不正、宛先が違うIDトークンは拒否される
- [ ] アクセストークンがlocalStorage・sessionStorageに保存されていない
- [ ] 画面を再読み込みしても、更新用トークンでログイン状態が戻る
- [ ] 一度使った更新用トークンを再利用すると、その系列がすべて失効する
- [ ] Originが自サイト以外の更新リクエストは拒否される
- [ ] 全端末ログアウト後は、どの端末の更新用トークンも使えない
- [ ] D1に更新用トークンの生の値が保存されていない
- [ ] E2Eで、ログイン済みの状態から始めて、再読み込み後もログインが続く
- [ ] 本番のビルド成果物に `__e2e__` が含まれていない（CIで確認）
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
