## 概要
誘いが成立した瞬間を、少しだけうれしい時間にする。2人のアイコン（灯りの色の丸）が寄って重なり、成立の青緑に変わる（約1.2秒）。そのあと「決まった！」と日時、相手、今ある成立後の操作を出す。持ち主が協議用モック（「今ひまと成立の案くらべ」）の案C「ふたつの灯りが重なる」を選んだ。

この PR は、持ち主の決定で、仕様書と実装を同じ PR にする（CLAUDE.md の「1タスク2PR」の例外）。

## データ
- サーバー：なし（マイグレーションなし）。「見たか」はサーバーに保存しない。
- 端末：localStorage の `kokohima.meetMomentSeen` に、演出を見た予定の ID（UUID）の配列を、新しいものから50件まで置く（下の「2.」）。

## 振る舞い

### 1. いつ流すか
- 流すのは、閲覧者から見て成立中（予定の `status` が `confirmed`）で、まだ終わっていない（`endsAt` が画面を開いた時刻より後）予定で、この端末でまだ演出を見ていないときだけ。予定ごとに1回。
- 流す画面と、そのきっかけ：
  - 誘いの詳細（`/invites/{id}`）：誘いが `confirmed` で `meetupId` があるとき。
    - 受信者が「行く」を押した直後（サーバーの応答で `meetupId` が入ってから。楽観的更新の間は流さない。送れなかったときも流さない）。
    - 送信者が「この時間なら」に「決める」を押した直後。
    - 相手が成立させたことを知って、最初に開いたとき（送信者が、相手の「行く」のあとに開く。受信者が、送信者の「決める」のあとに開く）。
  - 募集の詳細（`/broadcasts/{id}`）：募集が `decided` で `meetupId` があるとき（募集者が「決める」を押した直後、予定の参加者が決まったことを知って最初に開いたとき。お知らせ `broadcast_decided` の行き先）。
  - 成立した予定（`/meetups/{id}`）：お知らせ（`meetup_confirmed` の行き先）から開いたときなど、成立した予定を最初に開いたとき。
- 同じ予定は、どの画面で見ても1回だけ（誘いの詳細で見たら、成立した予定の詳細ではもう流さない）。
- 断り（今回は難しい）・見送り・期限切れ・取り消し（やっぱり難しい）・募集の締め切りでは、演出を出さない（静かに今までの表示）。演出のあとに「やっぱり難しい」を押したら、演出を消して今までの静かな表示（「やっぱり難しくなりました」）に戻す。
- 終わった予定・取り消された予定（募集の予定から抜けた人を含む）は、まだ見ていなくても流さない。
- 誘った側（成立させていない側）にも、最初に開いた1回だけ流す。
  - **判断してほしいこと**：誘った側にも流すか。選択肢は「流す」「押した側だけ」。推奨：流す（成立は2人のうれしさなので、押した側だけにしない）。この形で実装した。

### 2. 「見た」の記録（端末の中だけ）
- **判断してほしいこと**：「見たか」を端末の中に置くか、サーバーに置くか。推奨：端末の中（サーバーの列も API も要らず、ポリシーに1行足すだけ。端末ごとに1回ずつ流れるのは受け入れる）。この形で実装した。
- 流すかどうかは、予定の ID ごとに、その画面で最初に描いたときに一度だけ決める（記録したあとも、その画面を開いている間は出し続ける）。予定を参加者として読めて、成立中でまだ終わっていないと分かり、流すと決まったときに、端末の localStorage の `kokohima.meetMomentSeen`（予定の ID の配列）に足す。予定が読めなかった（通信・サーバーの失敗）・見つからない（404。参加者でない）・取り消された・終わった予定は記録しない（読めなかった予定は、次に読めたときに流す）。
- 置くのは予定の ID（UUID の形のものだけ）。予定の時間・名前・中身は置かない。サーバーには送らない。
- 新しいものから50件まで。あふれたら古いものから捨てる（捨てた予定をもう一度開いても、終わっていれば流さない）。
- 読めない・書けない（プライベートブラウズ、容量、壊れた値）ときは「見ていない」として扱い、画面を落とさない（書けなければ、次に開いたときもう一度流れるだけ）。
- ログアウト・すべての端末からのログアウト・退会・ログインが切れたとき（使っている間に切れた `becomeAnonymous` と、アプリを閉じている間に切れていて起動したときの確かめで分かったときの両方）に消す（同じ端末の次の人に残さない）。
- 端末ごとの記録なので、別の端末（スマホと PC）ではそれぞれ1回ずつ流れる。
- アクセストークンは今のままメモリだけ（CLAUDE.md「セキュリティ」）。localStorage に置くのは、この予定の ID の配列だけ。
- プライバシー ポリシーの「10. Cookie と、端末に置くもの」に1行足す（予告なし。T-19 決めたこと17。改定日は今の `REVISION_DATE_LINE` のまま）。

### 3. 演出（案C「ふたつの灯りが重なる」）
- 丸（直径72px、重なり20px、`meet-soft` の3pxの縁）が、外から寄って重なり（〜0.66秒）、灯り（`lamp`・`on-lamp`）から成立の青緑（`meet`・`on-meet`）に変わり、少しふくらんで戻る（合わせて1.2秒）。丸の並びの後ろが、灯りの色から青緑の色の光でふわっと光って消える（1.3秒）。
- そのあと、文字が下から順に出る（0.95秒から、60ミリ秒ずつずらして0.3秒）：「決まった！」（見出し）→ 日時（`formatRange`。例「10/10（土） 19:00〜23:00」）→ エリア（あれば）→ 「〇〇と会える」→ 成立後の操作。
- 背景は `meet-soft`。成立の画面の時間の欄（誘いの詳細の時間、成立した予定の詳細の青緑の帯）の代わりに出す（日時を二重に出さない）。ほかの欄（ひとこと・リンク・参加する人・「成立した予定を見る」・「やっぱり難しい」）は今のまま下に出す。
- 丸の中は表示名の1文字め（アイコンの画像は使わない。色が意味を運ぶため）。名前がない・退会した人は「？」。丸は飾りなので読み上げない（`aria-hidden`）。演出のまとまりは見出し「決まった！」の名前の付いた区画（`region`）。
- 動きは CSS のアニメーション（`apps/web/src/index.css` の `kh-meet-converge`・`kh-meet-glow`・`kh-meet-reveal`）だけで作る。ライブラリを足さない。JavaScript で時間を数えない。
- 色はトークンだけ（`lamp`・`on-lamp`・`meet`・`on-meet`・`meet-soft`・`meet-ink`）。夜のテーマでもトークンのとおりに変わる。赤やエラー色は使わない。
- `prefers-reduced-motion: reduce` では動かさない：`index.css` の共通の決まり（`animation: none !important`）で止まり、アニメーションのない形＝重なった青緑の丸と文字の一枚絵がすぐに出る。

### 4. 演出のあとの操作（今あるものだけ）
- 誘いの詳細・募集の詳細：演出の中に「カレンダーに追加（.ics）」（T-06 決定事項10 と同じ動き。成立した予定の詳細から部品にした `IcsButton`）。「成立した予定を見る」は今の場所に1つだけ（演出の中に重ねない）。
- 成立した予定の詳細：演出の中には操作を置かない（「カレンダーに追加（.ics）」「やっぱり難しい」は今の場所に1つずつ）。
- LINE で成立を知らせる操作は今はない（T-28 は招待リンクの共有だけ）ので、足さない（下の「スコープ外」）。Google カレンダーへの書き込みは今のまま自動（T-06）。

### 5. 3人以上（募集で決めたとき）の並べ方
- 自分を左に、ほかの参加者は予定の参加者の順（API の `participants` の順）に並べる。丸は自分を含めて4つまで。ほかの参加者が4人以上なら「自分・2人・+n」（最後の丸を「+n」）にする。
- 寄ってくる前のずれは、真ん中から外へ対称に：2つは ±74px、3つは −64・0・64px、4つは −60・−20・20・60px（丸が増えるほど小さくし、スマホの幅（390px）に収める）。
- 「〇〇と会える」の名前は2人まで並べ（「あき・そら」）、3人からは「あき・そらほか2人」。退会した人は「退会したユーザー」、名前のない人は「名前未設定の友達」（T-02・T-16 と同じ）。
- 宛先の人のうち予定の参加者でない人には、今までどおり決まったかを伝えない（募集の `meetupId` がその人には `null` なので、演出も出ない。T-05 の不変条件）。

## 認可と秘匿
- 閲覧者IDの使い方：変えない。演出に使う予定は、今の `GET /api/v1/meetups/{id}`（`meetup_participants.user_id = :viewer` の条件。T-04）で読む。参加者でない予定は404で、演出は出ない。
- 他人のデータに届かないことの保証：API を足さないので新しい経路はない。端末に置く予定の ID は、その人が参加者として読めた予定のものだけで、ほかの人の端末には届かない。ログアウトなどで消す。
- 区別させない応答（見せない／暇がない／募集の応答者など）：変えない。募集の参加者でない宛先の人には `meetupId` がなく演出も出ないので、決まったかどうかは今までどおり伝わらない。断り・期限切れ・取り消しは演出の有無でも区別させない（どれも出さない）。
- ログに出すものはない（演出は画面の中だけ）。
