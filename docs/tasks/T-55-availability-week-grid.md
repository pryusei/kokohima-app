# T-55 ここ暇タブを週の帯に作り直す

## 目的
ここ暇タブ（`/availability`）が縦に長く、「AIで探す」も分かりづらい、と持ち主から指摘があった。協議用のモックの案A（週の帯を土台に、案Cの「空き」の印を混ぜる）に作り直し、スマホ1画面で、入れる・取り消す・AIでお店を探すの入口まで届くようにする。

## 関係する要件
- F-03（ここ暇の設定）、F-04（時間帯プリセット）
- T-03・T-06・T-22・T-29 の画面、T-11（デザイン）

## スコープ
- やること：
  - 7日×昼・夕方・夜のマス目。押すとすぐ作る・取り消す・この日だけ外す（確認なし）。下に数秒「取り消す」
  - 「次の7日」で14日先まで。今日の過ぎた時間帯は押せない
  - カレンダーと連携していれば、空いているマスに青緑の点（T-06 の候補。API はそのまま、範囲を14日に）
  - 昼・夕方・夜に合わない時刻のここ暇をマスに時刻で出す。「時間を細かく決めて入れる」「くり返し」を1行のリンク＋シートに畳む
  - 「自分のここ暇」の縦の一覧・「カレンダーの空き」の欄・「ここ暇を追加」のボタンをなくす
  - 行きたいの欄の頭に「AIでお店を探す」のカード。行きたいを横にめくるカードにし、ボタンの崩れを直す
  - 単体テストと E2E を新しい画面に合わせる
- やらないこと（スコープ外）：
  - 案C の「友達もひま」（新しい読み取りになる）
  - 時間の区切りを変える（T-41）
  - 新しい API・データの形の変更

## 受け入れ条件
- [x] 390×844 で、週の帯・「取り消す」・「AIでお店を探す」の入口が1画面に収まる。件数で高さが伸びない
- [x] マスは高さ48px。名前に日付・時間帯・状態が入り、キーボードとスクリーンリーダーで使える。`prefers-reduced-motion` で動かない
- [x] 取り消し・失敗に赤を使わない。トークンと `apps/web/src/ui/` の部品を使う
- [x] 単体テストが追加され、通る
- [x] 仕様書でE2Eの対象にした流れのE2Eテストを直した（CI で回す）
- [x] 仕様書とコードに齟齬がない（画面が変わる T-03・T-06・T-22・T-29・T-11・docs/design/README.md も直した）
- [x] typecheck・lint・関係するテストが通る
