# T-19 プライバシー ポリシーと利用規約のページ

## 目的
`https://kokohima.app/privacy`（プライバシー ポリシー）と `https://kokohima.app/terms`（利用規約）を、ログインしなくても読めるページとして出す。Google の OAuth を本番の公開ステータスにするとき（T-12 決定事項7）に、同意画面に入れる URL にする。中身は、アプリが実際に保存するもの・外に渡すものと一致させる。

## 関係する要件
- 要求定義書「残りの論点」一般公開までに必須：Googleの審査要件とプライバシーポリシーへの反映（このタスクでは、プライバシー ポリシーの部分）
- 要求定義書「AI時代の攻撃を前提にした運用」：保存するデータを減らす（保存期間は docs/specs/T-17-retention.md「1. 保持期間の一覧」が正）
- F-01（ログイン）、F-02（カレンダー連携）、F-15（リンクのプレビュー）、F-16（通知）、F-17（退会）
- T-12 決定事項7（Google の OAuth を本番に。pryusei/kokohima-app#128 でマージ済み。先にこのページをデプロイする）
- issue：pryusei/kokohima-app#89（「削除した」の範囲）・#90（開示・削除の請求）・#91（利用規約・対象年齢）の一部

## スコープ
- やること：
  - 画面 `/privacy` と `/terms`（ログイン不要。SPA の経路）
  - プライバシー ポリシーと利用規約の本文（仕様書の「6.」「7.」の文案。最終の文言は利用者が決める）
  - ログインの画面・招待リンクの受け口の下に、2つのページへのリンク。設定に「このアプリについて」の節
  - 本番と同じ形の E2E（`release`）で、2つのページを開いて CSP の違反が0件であること
  - 制定日の仮の値「2026年◯月◯日」が残ったまま本番にデプロイしない検査
  - T-12 の人が行う作業3（Google の同意画面のブランディングに URL を入れる）と、要求定義書・T-17 の申し送り
  - 改定（仕様書の決めたこと11〜15）：外国の事業者に任せること（相当措置）の本文、規約の第5条3（画像の削除の求め）、7日前の予告（改定日・公表日の行、「この改定で変わるところ」の箇条書き、`deploy:prod` の日付の検査）、改定日のあとに予告の行と箇条書きを外すこと
- やらないこと（スコープ外）：
  - 英語版、ロゴ（同意画面に入れない。T-12 決定事項7）
  - Cookie の同意の帯（追跡の Cookie を使わないので要らない）
  - 開示・削除の請求に答える運営用の機能、漏えいのときの手順書（#90 の残り）
  - 障害のときの告知の仕組み（#91 の残り）
  - Google の審査（一般公開のとき）
