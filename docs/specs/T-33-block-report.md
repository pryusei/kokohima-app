# T-33 仕様書：ブロックと通報

- 状態：実装済み
- タスク票：docs/tasks/T-33-block-report.md
- 関係する要件：F-09 友達解除、F-24 ブロックと通報（この仕様で足す）、F-22 問い合わせ、要求定義書「未決事項」（ひとことの不適切利用への対策。#49）・「受容したリスク」。pryusei/kokohima-app#181（親 #178）
- 進め方：持ち主の決定で、仕様書と実装を同じ PR にする（1タスク2PRの例外）

## 概要
- 高校生を含めて一般公開する。新しい友達への初期の公開は「見せる」のまま（持ち主の決定）なので、嫌な相手をすぐ切れる手段を公開の前に入れる。
- 今は「ブロックなし、リンクを開き直せば友達に戻る」（F-09）で、通報もない（#49）。
- 友達の「…」のシートに、軽い順に「見せる／見せない → 友達を解除 → ブロック → 通報」を並べる。どれを選んでも相手には知らせない。
- ブロックは友達の解除と同じことをしたうえで、ブロックの間は、どちらの向きの招待リンクでも友達にならないようにする。ブロックされた側からは、解除されたのと区別できない。
- 通報は運営に届ける。問い合わせ（T-24）と同じ仕組み（outbox → Queue → Slack の非公開のチャンネル。届けたら D1 の本文を消す）を使う。

## 決めたこと
持ち主が示した既定の方針（1〜8）と、この仕様書で決めた細部（9〜）。

1. 「…」のシートは、友達の詳細・届いた誘い・届いた募集から開く。上から軽い順に：見せる／見せない → 友達を解除 → ブロック → 通報。上に1行「どれを選んでも〇〇さんには知らせません。」。説明の文は1画面1行まで。
2. ブロックの確認は1回（シートの中で）。ブロックすると、友達の解除と同じことが起きる（両方向の友達の行と、両方向の「見せる」の公開設定の行を消す。T-02・T-17「7.」）。進行中の誘い・募集・予定の扱いも解除と同じ（残す。T-04 決定事項6・T-05）。
3. ブロックしている間は、どちらの向きの招待リンクを開いても友達にならない。受け口は「このリンクは使えません」と同じ表示（期限切れ・取り消しと区別させない）。ブロックされた側からは「解除された」のと区別できない（API の応答の形・項目・エラーで区別させない）。
   - 受け入れること：ブロックされた側は、ブロックした人の招待リンク（グループに貼られて、ほかの人には使えるものなど）で、ブロックされたことが確かに分かる。未ログインで開く（API ならヘッダーなしで `lookup` を呼ぶ）と、ほかのリンクと同じく発行者の表示名とアイコンが見え（200）、ログインして開く（Bearer つき）と「このリンクは使えません」（404）になる。期限切れ・取り消しのリンクはどちらでも404なので、この違いからブロックが分かる。ほかの人には使えるリンクを未ログインでも開ける以上、避けにくい差として受け入れる。ログインした `lookup` の確かめは画面の表示のためで、守りではない。友達にならないことの守りは `accept` の SQL（人数を消費する `UPDATE` の条件の「どちらかの向きの `blocks` の行がない」）だけ。応答の形（本文・Cookie の消し方）は、期限切れ・取り消しと同じにし、それ以上は区別させない。
4. ブロックの解除は、設定の「ブロックした人」から。解除しても友達には戻らない（招待リンクでつながり直す）。
5. 通報は、理由を選ぶだけで送れる（何度も誘われる／ひとこと・リンクが不快／知らない人・なりすまし／会うのが不安な誘い／その他）。くわしく（任意、1000文字まで）。「ブロックもする」は最初から印。1行「危ないと感じたら、周りの大人か #9110 へ。急ぐときは110番」。誘い・募集から通報したときは、その誘い・募集（ひとこと・リンク・日時・エリア）を対象として一緒に送る。予定の中身（カレンダー）は持っていないので送らない。
6. 通報は運営に届ける。T-24 と同じ outbox → Queue → Slack。回数の上限は1人直近24時間に5件。通報したことは相手に伝えない。
7. 赤やエラー色を使わない。ブロック・通報の結果も静かに出す。
8. 保存する情報・外に渡すもの・保存期間が変わるので、T-19「9.」のとおり、プライバシー ポリシー（と利用規約）を同じ PR で直し、本格稼働までは予告なしで改定する（T-19 決めたこと17）。改定日（効力が生じる日）と始める日は、マージしてデプロイする日。
9. ブロック・通報できる相手は、閲覧者の今の友達か、閲覧者に届いた誘い・募集の送り主だけ（自分・関係のない人・存在しない人は404）。届いた誘い・募集からなら、相手が先に解除していても、ブロック・通報できる。
10. 通報の Slack の文には、通報した人のメールアドレスと名前を入れない（返事をしない前提。利用者を区別する番号だけ）。
11. 届け先は、問い合わせと同じ `#kokohima-contact`（同じ webhook）。見出しで「通報：<理由>」と区別する。
12. 友達の詳細の「自分の暇を見せる」と「友達を解除」は、「…」のシートの中に移す（同じ所に軽い順に並べるため）。友達タブの一覧の「自分の暇を見せる」のスイッチは今のまま。
13. 通報への対応の目安（例：48時間）は、規約・ポリシーに約束しない（運営者1人のため。「確認事項」2）。

## API
`api-conventions` に従う。例外は下に理由を書く。

| メソッド | パス | 認証 | 入力（Zodスキーマ名） | 出力 | 主なエラー |
| --- | --- | --- | --- | --- | --- |
| POST | `/api/v1/blocks` | Bearer（`requireActiveSession`） | JSON：`createBlockRequestSchema` `{ userId, subject? }` | 204 | 404 `not_found`（始める日より前・相手を確かめられない）、400、401 |
| GET | `/api/v1/blocks` | Bearer | query：`limit`、`cursor` | 200：`blockedUserPageSchema` `{ items: [{ user: historyProfile, blockedAt }], nextCursor }` | 404（始める日より前）、400 |
| DELETE | `/api/v1/blocks/{userId}` | Bearer（`requireActiveSession`） | なし | 204 | 404（始める日より前・閲覧者のブロックがない） |
| POST | `/api/v1/reports` | Bearer（`requireActiveSession`・`requireSameOrigin`）。`Idempotency-Key` を受け付ける | JSON：`reportRequestSchema` `{ userId, reason, details?, subject?, alsoBlock }` | 204 | 404（始める日より前・相手を確かめられない）、400、401、409 `request_in_progress`、422 `idempotency_key_mismatch`、429 `rate_limited`（`Retry-After`） |
| POST | `/api/v1/invite-links/lookup` | なし（Origin）。**Bearer があれば読む** | 変更なし | 変更なし | 404：どちらかの向きのブロックがあるときも、使えないリンクと同じ |
| POST | `/api/v1/invite-links/accept` | 変更なし | 変更なし | 変更なし | 404：どちらかの向きのブロックがあるときも、使えないリンクと同じ |

- スキーマは `packages/shared/src/schemas/safety.ts`（どれも `.strict()`）。
  - `safetySubjectSchema`：`{ type: "direct_invite" | "broadcast", id: uuid }`。中身（ひとことなど）は受け取らず、サーバーが閲覧者の権限で読む。
  - `reportRequestSchema.details`：問い合わせの `contactBodySchema` と同じ（正規化・コードポイントで1〜1000文字・使えない文字）。空なら項目ごと省く。
  - 値：`REPORT_REASONS`・`REPORT_REASON_LABELS`・`REPORT_DETAILS_MAX`（1000）・`REPORT_DAILY_LIMIT`（5）・`REPORT_LIMIT_WINDOW_HOURS`（24）。
- 例外：
  - ブロックは `POST /blocks`（作る）と `DELETE /blocks/{userId}`（消す）にする。ブロックした人の1件を取る経路はないので、201 と `Location` は返さず204。何度送っても204（最初の時刻のまま）。
  - `POST /blocks`・`DELETE /blocks/{userId}` は `Idempotency-Key` を受け付けない。何度送っても結果が同じなため（T-10 の `revoke` と同じ）。
  - `POST /reports` は二重に実行すると Slack に2通届くので `Idempotency-Key` を受け付ける（T-24 と同じ）。作ったものを読む経路がないので204。
  - 通報は、外の事業者に情報を送る操作なので `requireSameOrigin` を重ねる（T-24 と同じ）。ミドルウェアの順番も T-24 と同じ：始める日 → `requireAuth` → `requireActiveSession` → `requireSameOrigin` → 本文の上限（8192バイト）→ `idempotent` → 検証 → 受け付け。
  - `lookup` は認証を求めないまま、`Authorization: Bearer` があって正しければ閲覧者として読む（`optionalViewerId`）。正しくなければ未ログインと同じに扱い、401 にしない。

## 振る舞い

### 1. 「…」のシート（`PersonActions`）
- 置き場所：友達の詳細（`/friends/{id}`）、届いた誘いの詳細、届いた募集の詳細の、見出しの行の右に「…」（`aria-label`「〇〇さんへの操作」）。送った誘い・送った募集、退会した相手には出さない。
- 開くと、同じシートの中身を置き換えて出す（シートを重ねない）。「戻る」で元の中身に戻る。
- フォーカス：「…」は開くと消えるので、開いたとき・中身を置き換えたとき（通報のフォーム、結果）に、操作の領域（`role="group"`、`aria-label`「〇〇さんへの操作」、`tabIndex=-1`）へフォーカスを移す。「戻る」で閉じたら、出し直した「…」へフォーカスを戻す（`usePersonActionsToggle`）。
- 並び（上から）：
  1. 1行「どれを選んでも〇〇さんには知らせません。」（説明の文はこの1行だけ）
  2. 「自分の暇を見せる」のスイッチ（今の友達のときだけ。楽観的更新、失敗したら戻す。T-02）
  3. 「友達を解除」（今の友達のときだけ）。押すと「〇〇さんとの友達を解除する」と「やめる」（確認1回）
  4. 「ブロック」。押すと「〇〇さんをブロックする」と「やめる」（確認1回）。確かめている間は、上の1行を「〇〇さんには知らせません。友達の解除と同じになり、招待リンクでもつながらなくなります。」に置き換える
  5. 「通報」。押すと通報のフォーム（「4.」）
  6. 「戻る」
- 今の友達かは `GET /friends/{id}` で読む（404 なら友達でない。キーは `friends.status(id)`）。届いた誘い・募集からは、友達でなくても「ブロック」「通報」を出す。
- 始める日（「8.」）より前は、「ブロック」「通報」を出さない（見せる・解除だけ）。
- 結果は静かに出す（`role="status"`、ふつうの文字の色）：「友達を解除しました。」「ブロックしました。」「送りました。」「送りました。ブロックもしました。」と「戻る」。友達の詳細では、解除・ブロックのあとの「戻る」で友達タブへ移る（解除と同じ）。誘い・募集の詳細では元の中身に戻る。
- 失敗は「できませんでした。もう一度お試しください。」を静かに出し、シートに留まる。

### 2. ブロック（`POST /blocks`）
1. 相手を確かめる（`actionableTarget`）：
   - `subject` がなければ、閲覧者側の友達の行（`friendships.user_id = 閲覧者 AND friend_id = userId`）があること。
   - `subject` があれば、その誘い（`direct_invites.recipient_id = 閲覧者`）か募集（`broadcast_recipients.user_id = 閲覧者`）を閲覧者が受け取っていて、送り主が `userId` であること。
   - `userId` が閲覧者自身なら、いつも確かめられない。
   - 確かめられなくても、閲覧者がすでに `userId` をブロックしていれば204（二度押し）。ほかは404。
   - 届いた誘い・募集の送り主が退会していても、確かめられる（T-16 で、退会した人の誘い・募集は相手の履歴に残るため）。このときは204を返し、ブロックの行は書かない（下の2.）。画面は退会した相手に「…」を出さないので、シートを開いている間に相手が退会したときか、API を直接呼んだときだけ起きる。
2. 1つの batch で：`blocks` に行を書く（`INSERT OR IGNORE`。閲覧者か相手のどちらかが退会していれば書かない。相手の退会の削除はもう済んでいて、書くと消えずに残るため。同じ文の中で `users.withdrawn_at` を確かめる）、両方向の `friendships` を消す、両方向の `sharing_policies` の「見せる」の行を消す（`unfriendPurgeSharingStatements`。解除と同じ）。
3. 相手には知らせない。outbox に何も書かない（解除と同じ）。
- ブロックのあと：
  - 友達でないので、新しい誘い（T-04）・募集の宛先（T-05）・ここ暇（T-03）・行きたい（T-22）は、どちらからも届かない・見えない（友達の条件のまま）。
  - 進行中の誘い・募集・成立した予定は残す（解除と同じ。返答もできる）。残した誘いへの返答のお知らせも今のとおり届く（「確認事項」3）。
  - 招待リンク：
    - `lookup`：Bearer があって、閲覧者と発行者の間にどちらかの向きのブロックがあれば、使えないリンクと同じ404（招待 Cookie も消す）。
    - `accept`：人数を消費する `UPDATE` の条件に「どちらかの向きの `blocks` の行がない」を足す（同じ文の中で確かめる）。0行なら、ほかの使えないリンクと同じ404（Cookie も消す）。
    - 未ログインの `lookup` では、ブロックを確かめられないので、発行者の名前が出る。ログインして `/invite` に戻ると、Bearer つきの `lookup` で「このリンクは使えません」になる。
  - 受け口（`InvitePage`）：URL のトークンは開いてすぐ消す（今のとおり）。`lookup` は、ログインの確かめ（`status` が `checking` でなくなる）を待ってから、ログインしていればアクセストークンを付けて送る。

### 3. ブロックした人とやめる（`GET /blocks`・`DELETE /blocks/{userId}`）
- 一覧は、閲覧者がブロックした人だけ（`WHERE blocker_id = 閲覧者`）を、ブロックした新しい順（同じなら相手 ID の降順）。カーソルは T-02 と同じ形。相手は履歴の相手のプロフィール（`getHistoryProfiles`。友達でないのでアイコンは null、退会した人は `withdrawn`）。
- やめる：`DELETE FROM blocks WHERE blocker_id = 閲覧者 AND blocked_id = ?`。消せなければ404。友達には戻さない。
- 画面：設定のトップの最初の一覧の「通知の設定」の下に「ブロックした人」（`/settings/blocks`、`SubScreen`）。説明の1行「ブロックをやめても友達には戻りません。つながるときは招待リンクを送り直してください。」。各行に名前と「ブロックをやめる」。いなければ空の表示「ブロックした人はいません」。始める日より前は、行を出さず、`/settings/blocks` は知らない経路と同じ扱い。

### 4. 通報（`POST /reports`）
- 受け付けの順番：
  1. 相手を確かめる（「2.」の1と同じ。ブロックのあとの二度押しの扱いはない）。できなければ404。
  2. 1つの文で、退会していないことと回数の上限（直近24時間に5件未満。`UserReported` の outbox の行を `userId` で数える）を確かめて、outbox に行を書く（T-24 の `insertIfAllowed` に型を渡す）。問い合わせの回数とは別に数える。
  3. 書けなければ、退会していれば401、そうでなければ429（`Retry-After` は窓のいちばん古い行が24時間を過ぎるまでの秒数。T-24 と同じ）。ブロックもしない。
  4. 書けたら、`alsoBlock` なら「2.」の2のブロックをする。
  5. 204。受け付けのログは出さない。上限を超えたときだけ `{ event: "rate_limited", group: "reports" }`（利用者 ID は出さない）。
- 対象の写し：`subject` があれば、閲覧者の権限で読んだ誘い・募集の日時・エリア・ひとこと・リンクを payload に入れる。予定の中身（カレンダー）は持っていないので入らない。
- 画面（「…」のシートの中、`ReportForm`）：
  - 見出し「〇〇さんを通報」
  - 理由のチップ5つ（1つだけ選べる）。選ぶまで「運営に送る」は押せない
  - 「くわしく（なくても送れます）」の欄と文字数（`CharCount`。1000を超えたら押せない）
  - チェックボックス「ブロックもする」（最初から印）
  - 1行「危ないと感じたら、周りの大人か #9110 へ。急ぐときは110番」（説明の文はこの1行だけ）
  - 「運営に送る」と「戻る」
  - 冪等キーは T-10 の `useIdempotencyKey`。通信できない・5xx は同じ内容で送り直すと同じキー。
  - 失敗は静かに：429「今日はこれ以上送れません。ブロックは、前の画面からできます。」、ほか「送れませんでした。もう一度お試しください。」。入力は残す。401 は API クライアントのまま。

### 5. 届ける処理（consumer）
- `UserReported` を dispatch の「常に流す型」と `ID_ONLY_TYPES` に足す（Queue のメッセージは `payload: "{}"`）。consumer は受付番号で D1 の行を読む（`deliverReport(ctx, outboxId)`）。
- 手順は T-24「3.」と同じ：行がない・届け済みなら何もしない → 通報した人が退会していたら送らずに中身を消す → 文を組み立てる → webhook の URL を確かめる（`CONTACT_SLACK_WEBHOOK_URL`、`hooks.slack.com/services/`）→ 送る（5秒、転送に従わない、200 以外は投げて再試行）→ 届けたら中身を消す → 送る間に退会していたら `report_delivered_after_withdrawal`（受付番号だけ）を出す。
- Slack の文（`buildReportSlackMessage`）。T-24「4.」と同じ決まり（`plain_text`・`emoji: false`・`&`・`<`・`>` のエスケープ・リンクの展開を止める・3000文字ずつの `section`）：
  - `text` と `header`：「通報：<理由>」
  - 欄：通報した人（ID）・通報された人（ID）・受付（日本時間）・受付番号・ブロック（した／していない）
  - 対象があれば：対象（誘い／募集と ID）・日時（日本時間）・エリア、続けて「リンク：…」「ひとこと：…」の `section`
  - くわしくがあれば「くわしく：…」の `section`
  - メールアドレス・名前は入れない（決めたこと10）

### 6. 退会・保持期間
- 退会（T-16 の入口を止める段）：
  - social の `withdrawalPurgeStatements` に `DELETE FROM blocks WHERE blocker_id = ?1 OR blocked_id = ?1` を足す（ブロックした・された、の両方）。
  - `PERSONAL_OUTBOX_TYPES` に `UserReported` を足す（通報した人の ID で消す。まだ届けていなければ届かない）。
  - 通報された人が退会しても、その人についての通報は消さない（通報した人のもの。届けたら中身は消える）。
- 保持期間（T-17「1.」に足す。`retention.ts` の値は増やさない）：
  - `blocks`：やめたとき・どちらかが退会したとき（期限なし）。
  - 通報の outbox の中身：Slack に届けたとき（届かなかった行は処理から `RETENTION.processedOutboxDays` 日で行ごと消える）。
  - Slack のメッセージ：対応を終えたら運営者が消す。遅くとも投稿から `PLATFORM_RETENTION.contactSlackDays` 日（T-24「6.」と同じ保持の設定）。

## 認可と秘匿
- 閲覧者IDの使い方：すべて `requireAuth` の閲覧者だけを使う。body の `userId` と `subject.id` は「閲覧者の持ち物の中から探すキー」にだけ使う。
  - ブロック・通報の相手：閲覧者側の `friendships` の行か、閲覧者が受け取った誘い・募集（`recipient_id = 閲覧者`・`broadcast_recipients.user_id = 閲覧者`）を SQL の条件に入れて読む。
  - 一覧・やめる：`WHERE blocker_id = 閲覧者`。
  - 通報の送り主はいつも閲覧者（`.strict()` で送り主を指定できない）。
- 他人のデータに届かないことの保証：上の条件を SQL に入れる。取得後にアプリ側で絞り込まない。関係のない人・存在しない人・自分・送った側の誘い・送り主の違う対象は、どれも同じ404。ブロックされた側は、やめる・一覧で、ブロックした人のブロックに届かない。
- 区別させない応答：
  - ブロックされた側：友達の一覧・詳細・ここ暇・行きたいは、解除と同じ（404・一覧にない）。招待リンクの `lookup`・`accept` は、期限切れ・取り消しと同じ404（本文・Cookie の消し方も同じ）。
  - 通報されたこと・ブロックされたことは、誰にも知らせない（お知らせ・プッシュ・メール・outbox の相手あての行を作らない）。
- ログ：通報の内容・理由・利用者 ID を出さない。
