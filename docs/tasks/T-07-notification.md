# T-07 通知（Webプッシュとメール）

## 目的
誘い・募集・成立・キャンセル・友達追加・自動取り消し・新端末のログインを、本人に知らせる。通知の中身はアプリの「お知らせ」一覧で読み、プッシュとメールには相手の名前や誘いの内容を載せない。

## 関係する要件
- F-06：実予定でここ暇を自動で取り消したら本人に通知する（まとめて1件）
- F-08：友達追加の通知と、通知から公開をオフにする導線
- F-16：通知は Webプッシュとメール
- NF-02：外部連携（通知）は Queues 経由で、失敗時は再試行する
- NF-07：1日の上限と、ユーザーごとの停止設定。自動取り消しはまとめて通知する
- 要求定義書の未決事項「通知の種別と頻度、メールにする通知、停止設定、自動取り消しのまとめ通知」（この仕様書で決める）
- セキュリティ設計：新端末のログインをメールで本人に通知する、通知メールにログイン用のリンクを入れない、送信ドメインの SPF・DKIM・DMARC

## スコープ
- やること：
  - outbox の通知の型を Queue に流し、受け取り手ごとの「お知らせ」を作る（T-06 の outbox → Queue → consumer を使う）
  - お知らせ一覧・未読数・既読の API と画面
  - Webプッシュ（中身なし。VAPID の署名だけ）の購読の登録・解除、送信、Service Worker
  - メール（Resend）：プッシュの購読がない人へのお知らせと、全員への新端末のログイン
  - 種別ごとのオン／オフと、1日の上限
  - 友達追加のお知らせから「この人に見せない」にする導線
  - 画面（仮）：お知らせ一覧、通知の設定
- やらないこと（スコープ外）：
  - 通知の文言とデザインの最終版（デザインのタスク）
  - 週次通知（Phase 2）、ネイティブアプリのプッシュ、メールの開封の計測
  - 送信ドメインの DNS（SPF・DKIM・DMARC）の設定そのもの（人が行う。手順だけ書く）

## 受け入れ条件
- [ ] 誘い・募集・成立・キャンセル・友達追加・自動取り消し・連携の失効が、受け取り手のお知らせ一覧に1件ずつ出る（同じイベントが2回届いても1件）
- [ ] プッシュを許可した端末に、中身のないプッシュが届き、押すとお知らせ一覧が開く。プッシュの本文に相手の名前・誘いの内容が入らない
- [ ] プッシュの購読がない人には、同じお知らせがメールで届く。新端末のログインは全員にメールで届く。メールにログイン用のリンクが入らない
- [ ] 種別ごとに止められ、止めた種別はプッシュもメールも送らない（お知らせ一覧には残る）。1日の上限を超えた分は送らない
- [ ] 断り・期限切れ・キャンセルのお知らせを、赤やエラー色でなく静かに表示する。手の断りと自動の断りを区別しない
- [ ] 友達追加のお知らせから、その友達に「見せない」にできる
- [ ] 通知の有無や件数から、「見せない相手」や募集の応答者の有無を推測できない
- [ ] 他人のIDでは取得・更新できないテストがある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
