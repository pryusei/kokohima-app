# T-16 仕様書：退会

- 状態：下書き
- タスク票：docs/tasks/T-16-withdrawal.md
- 関係する要件：F-17、要求定義書のイベント表「UserWithdrew」、データの最小化。issue pryusei/kokohima-app#37

## 概要
- 利用者が設定のアカウントから退会できるようにする。確認の画面のあと、その場で本人のデータを消す（取り消しの猶予は設けない。利用者と決めた）。
- 今の外部キーはどれも `ON DELETE CASCADE` なので、利用者の行を消すと、相手の誘い・募集・成立した予定まで消える。F-17 の「相手側の履歴は『退会したユーザー』と表示」と逆の動きになる（#37）。
- そこで、利用者の行は **ID だけを残した「抜け殻」** にし、本人のデータ（名前・メール・ログインの紐づけ・ここ暇・友達・連携・お知らせ・書いた内容）を消す。相手の履歴は残り、相手の画面には「退会したユーザー」と出る（利用者と決めた）。
- 進行中の予定と返事待ちの誘い・募集は、退会した人が「やっぱり難しい」を押したのと同じ扱いにする（利用者と決めた）。

## 決めたこと（利用者の回答）
1. 利用者の行は ID だけ残す（行ごと消して参照を空にする形にはしない）。
2. 退会した人が書いた、過去の誘い・募集の「ひとこと」「エリア」「リンク」は消す。
3. これからの成立した予定と、返事待ちの誘い・募集は「やっぱり難しい」と同じ扱いにする。
4. 確認の画面のあと、すぐに消す。同じ Google でまたログインすると、新しい利用者になる。

## API
`api-conventions` に従う。

| メソッド | パス | 認証 | 入力（Zodスキーマ名） | 出力 | 主なエラー |
| --- | --- | --- | --- | --- | --- |
| DELETE | `/api/v1/me` | Bearer＋有効なセッション＋同じオリジン | body：`withdrawRequestSchema` `{ confirm: "withdraw" }` | 204（更新用トークンの Cookie を消す） | 400（確認の値が違う）、401 |

- 退会させられるのは閲覧者本人だけ。経路に利用者の ID は入らない（他人の ID を渡す口がない）。
- `requireAuth`・`requireActiveSession`・`requireSameOrigin` を通す（T-01 のログアウトと同じ）。
- 確認の値 `"withdraw"` は、誤操作（画面の二重の押下や、ほかの経路のつもりの要求）で退会しないための目印。画面の確認とは別に持つ。
- `publicProfileSchema`（T-02）に `withdrawn: boolean` を足す。退会した人は `{ id, displayName: null, avatarUrl: null, withdrawn: true }`。項目の追加なので互換は壊れない。

## データ（マイグレーション `0011_withdrawal.sql`）
- `users` に `withdrawn_at INTEGER`（NULL なら利用中）を足す。
- 外部キーの CASCADE は変えない（利用者の行を消さないので、相手の行は消えない）。

## 振る舞い

### 退会の手順（`DELETE /api/v1/me` の中で、この順に行う）
どの手順も、何度呼んでも同じ結果になる（途中で失敗しても、もう一度押せば続きから終わる）。最後の手順で、セッションが消える。

1. **カレンダーの連携の解除**：T-06 の連携の解除（`disconnectGoogle`）と同じ処理を行う。Google の更新用トークンの revoke（失敗しても続ける）と、連携の行の後始末。
2. **これからの成立した予定**：退会した人が参加者（抜けていない）で、開始前の `confirmed` の予定ごとに、本人が「やっぱり難しい」を押したのと同じ遷移を行う。
   - 個別の誘いの予定：`cancelMeetup`（T-04）。`MeetupCancelled` が出て、相手に定型文で知らせ、カレンダーから消える（T-06・T-07）。
   - 募集の予定：`leaveMeetup`（T-05）。`MeetupLeft` が出て、残りの参加者に知らせ、カレンダーのタイトルが直る。
3. **返事待ちの誘い**（`pending`・`counter_proposed`）：
   - 退会した人が受信者で `pending`：「今回は難しい」と同じ遷移（`DirectInviteDeclined`。送信者に知らせる）。
   - それ以外（退会した人が送信者のもの、`counter_proposed` のもの）：通知を出さずに終える。期限 `expires_at` を今にし、読むときに期限切れになる（T-04 の「期限切れは保存せず、読むときに決める」に合わせる）。
4. **募集**：
   - 退会した人が募集者で `open`：期限 `expires_at` を今にする（通知なし。宛先の人には「締め切りました」）。
   - 退会した人が宛先の人で応じている：応じるのをやめる（T-05 の「応じるのをやめる」と同じ。通知なし）。
5. **本人のデータの削除**（1つの batch。先頭で `UPDATE users SET withdrawn_at = ? ... WHERE id = ? AND withdrawn_at IS NULL` の条件付きで抜け殻にする）：
   - `users`：`display_name`・`avatar_url`・`email` を NULL に、`withdrawn_at` を今に。
   - 行を消す：`user_identities`（同じ Google でのログインが新しい利用者になる）、`sessions`（更新用トークンも）、`login_codes`、`invite_links`、`friendships`（両方向）、`sharing_policies`（両方向）、`presets`、`availabilities`、`recurrence_rules`（例外も）、`calendar_connections`・`calendar_oauth_states`・`ics_tokens`、`notifications`（本人あて）、`push_subscriptions`、`notification_preferences`、`notification_daily_counts`（本人の行）、`idempotency_keys`。
   - 書いた内容を消す：退会した人が送信者の `direct_invites`、募集者の `broadcasts` の `area`・`message`・`url` を NULL に。その誘い・募集の `link_preview_refs` を消す（結果の行は T-08 の掃除で消える）。
   - 残すもの：誘い・募集・予定・参加者・宛先の行（相手の履歴）、相手あてのお知らせ（`actor_id` は退会した人の ID のまま）、outbox の行（ID と時刻だけ）。
6. 応答で、更新用トークンの Cookie を消す（T-01 のログアウトと同じ）。

- 退会した人が受け取ったお知らせを作る処理（consumer）は、`users` が退会済みならお知らせを作らない（`INSERT ... WHERE EXISTS users` の条件に `withdrawn_at IS NULL` を足す）。
- 退会済みの利用者に誘い・募集を送ることはできない（友達でなくなるため、T-04・T-05 の「友達であること」の判定で404）。
- Google カレンダーに残る予定：開始前の予定は手順2で消える。過去の予定は相手のカレンダーにそのまま残る（相手のカレンダーの中身なので触らない。受け入れるリスク：タイトルに退会した人の表示名が残る）。

### 退会のあとのアクセストークン
- アクセストークンは最長10分有効（T-01）で、退会しても手元に残る。
- 書き込みの要求（`GET`・`HEAD` 以外）は、すべて `requireActiveSession` を通す。セッションが消えているので401になる。今 `requireAuth` だけを通している書き込みの経路に足す（実装PRで一覧にする）。
- 読み取りは、トークンが切れるまで通るが、本人のデータは消えていて、友達もいないので、何も見えない（受け入れる）。

### 相手の画面での表示
- 公開プロフィール（`getPublicProfiles`）は、退会した人を `withdrawn: true` で返す。
- Web は、`withdrawn` のとき名前の代わりに「退会したユーザー」と出す（「名前未設定の友達」とは区別する）。誘い・募集・予定・お知らせの一覧と詳細のどれも同じ。
- 退会した人あての誘いの状態は、上の手順どおり（断られた・期限切れ）に見える。赤やエラー色は使わない。

### 画面（設定のアカウント `/settings/account`）
- 「退会する」のボタンを、ほかの操作から離して置く（T-11 で作らなかった欄）。
- 押すと確認の画面：消えるもの（名前・ここ暇・友達・連携・お知らせ）と、相手の履歴には「退会したユーザー」と残ること、これからの予定は「やっぱり難しい」になること、取り消せないことを書く。「退会する」と「やめる」。
- 退会したら、手元のアクセストークンを消し、ログインの画面に「退会しました」と静かに出す。
- 失敗したら「退会できませんでした。もう一度お試しください」（赤を使わない）。

## 認可と秘匿
- 閲覧者IDの使い方：退会させるのは閲覧者本人だけ。経路にも本文にも利用者の ID を受けない。
- 他人のデータに届かないことの保証：消す行はどれも `user_id = 閲覧者`（友達・公開設定は両方向で閲覧者が片方）の条件で選ぶ。相手の行（誘い・予定の参加者・相手あてのお知らせ）は消さない。
- 区別させない応答：退会した人は、相手からは「友達でない人」と同じに見える（ここ暇は見えず、誘いは404）。「見せない」相手・暇がない相手との区別は今までどおり。
- 秘密の扱い：Google の更新用トークンは revoke してから消す（T-06）。ログに利用者の ID・メール・名前を出さない。出すのは `user_withdrew` の event 名と、消した行の数だけ。

## テスト計画

### 単体テスト（実装PRで必須）
- [ ] 退会すると：`users` が抜け殻（名前・メールが NULL、`withdrawn_at` あり）。手順5の表の行が消え、相手の誘い・予定・参加者・宛先・相手あてのお知らせは残る。
- [ ] 書いた内容：退会した人が送った誘いと作った募集の `area`・`message`・`url` が NULL になり、リンクのプレビューの参照も消える。相手が送った誘いの内容は残る。
- [ ] これからの予定：個別の誘いの予定は `cancelled` になり `MeetupCancelled`、募集の予定は退会した人だけが抜けて `MeetupLeft`。開始後の予定・抜けた予定は触らない。
- [ ] 返事待ち：受けた `pending` は `declined` と `DirectInviteDeclined`。送った誘い・`counter_proposed` は通知なしで期限切れ。募集者の `open` の募集は期限切れ（宛先の人には `closed`）。応じていた募集は応じていない状態に。
- [ ] カレンダー：連携していれば revoke を呼び、連携の行が消える。revoke が失敗しても退会は終わる。
- [ ] ログインし直し：同じ Google の `sub` でログインすると、新しい利用者 ID になる。
- [ ] アクセストークン：退会のあと、同じアクセストークンで書き込みの経路が401。更新用トークンでの更新も401。
- [ ] 何度呼んでも同じ：途中で失敗させたあともう一度呼ぶと、終わりまで進む。終わったあとは401（セッションがない）。
- [ ] 入力：確認の値がない・違うと400で何も変わらない。同じオリジンでなければ拒否。
- [ ] 他人のIDでは取得・更新できない：経路に ID を渡す口がなく、ほかの利用者のデータ（その人の友達・ここ暇・お知らせ）は消えない。
- [ ] 相手の表示：公開プロフィールが `withdrawn: true`。友達の一覧・「みんな」から消え、誘いは404。退会した人の ID を `actor_id` に持つお知らせは残り、`actor` が退会済みとして返る。
- [ ] お知らせ：退会したあとに処理された、退会した人あてのイベントからは、お知らせを作らない。
- [ ] ログ：`user_withdrew` に ID・メール・名前が出ない。
- [ ] Web：退会の確認の画面、成功でログインの画面と「退会しました」、失敗の静かな文言。`withdrawn` の相手は「退会したユーザー」と出る（誘い・予定・お知らせ）。

### E2Eテスト（対象にする利用者の流れ）
- [ ] A と B が友達で、成立した予定がある → A が設定から退会 → A はログインの画面に「退会しました」。B の成立した予定は「やっぱり難しい」になり、お知らせが届き、相手は「退会したユーザー」。B の友達一覧から A が消える。

## 実装PRで直すもの
- 要求定義書：F-17 に「ID だけ残す」「書いた内容も消す」「進行中は『やっぱり難しい』と同じ」。イベント表の `UserWithdrew` を、退会は outbox のイベントを作らず既存のイベント（`MeetupCancelled`・`MeetupLeft`・`DirectInviteDeclined`）で相手に伝える、に直す。
- T-01（アカウントの画面、ログインし直しは新しい利用者）・T-02（公開プロフィールの `withdrawn`）・T-04〜T-07 の退会の申し送りを、この仕様書への参照に置き換える。
- T-11 の「23 アカウント」の退会の欄。
- `invitation-domain` スキルの用語表に「退会したユーザー」。

## スコープ外
- 退会の取り消し・猶予期間。
- D1 のバックアップ（Time Travel）と、外部サービス（Resend の送信の記録、Google）に残るデータ（#89）。
- 成立数の集計（NF-08。#46）・監査ログ（#41）。作るときに退会の扱いを決める。
- 相手の Google カレンダーに残る、過去の予定のタイトル。
- アカウント連携（#45）。
