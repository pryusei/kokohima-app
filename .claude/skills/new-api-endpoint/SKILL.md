# APIエンドポイントの追加

先に `api-conventions` スキルを読み、パス・エラー形式・ステータスコードをそろえる。

1. 入力はスキーマで検証し、各文字列に上限を設ける（ひとこと・エリア・表示名など）
2. 認証済みの閲覧者IDをapplication層に渡す。リクエストのbodyやqueryのユーザーIDを信用しない
3. 取得系は、閲覧者IDと友達関係・公開設定をSQLの条件に入れる。取得後にアプリ側で絞り込まない
4. 状態変更は集約のメソッドを呼び、条件付きUPDATEで保存。外部連携はoutboxに書く
5. 存在しない・権限がない・見せない設定は、すべて404の `not_found` を返す（存在の有無を漏らさない）
6. テストを書く：正常系、入力検証、期限切れ、そして「他人のIDでは取得・更新できない」
7. `pnpm typecheck` と追加したテストを実行し、結果を示す
