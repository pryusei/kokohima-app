# T-04 個別の誘い（送信・返答・成立）

## 目的
友達1人に、日時を決めて誘い（「あそぼ」／「ここどう？」）を送れるようにする。受け取った人は「行く」「今回は難しい」「この時間なら」の3つで返答でき、行くと決まれば成立した予定になる。断りや期限切れで理由が伝わらない、静かな流れを作る。

## 関係する要件
- F-10：個別の誘い（日時、エリア（任意）、ひとこと、リンク（任意）、期限（送信時に選択））
- F-12：返答（行く／今回は難しい／この時間なら。断りは柔らかい定型表現に統一）
- F-13：成立（カレンダーへの登録は T-06。ここでは成立した予定を作るまで）
- F-14：成立後のキャンセル（定型の「やっぱり難しい」のみ。再調整しない）
- 要求定義書「状態遷移とビジネスルール」「ドメイン設計（DirectInvite の不変条件）」「悪用対策（送信上限1日20件）」
- T-03 の申し送り：「あそぼ」「ここどう？」の判定と相手の枠の表示には、見せてもらっている枠だけを使う（`visibleSlotsFor`）

## スコープ
- やること：
  - 誘いの送信（友達だけ、自分には送れない、1日20件まで）。「あそぼ」「ここどう？」の判定
  - 受信・送信した誘いの一覧と詳細
  - 返答（行く／今回は難しい／この時間なら）、「この時間なら」への送信者の決定（決める／見送る）。決めないまま代わりの時間の開始を過ぎたら期限切れ（決定事項8）
  - 期限切れ（返答できなくなる。誰にも通知しない）
  - 成立した予定の作成・一覧・詳細と、「やっぱり難しい」
  - outbox へのイベントの書き込み（通知とカレンダーへの書き込みは、それぞれ T-07・T-06 で読む）
  - 画面（仮）：誘いタブ（受信／送信／成立）、誘いの作成、誘いの詳細と返答、成立した予定。「みんな」と友達の詳細から誘いを作れるようにする
- やらないこと（スコープ外）：
  - 募集（T-05。送信上限の「誘い・募集あわせて」の募集の分は T-05 で足す）
  - カレンダーへの登録、.ics（T-06）。ここ暇の自動取り消しによる自動の「今回は難しい」（T-06）
  - 通知（T-07）。OGPプレビュー（T-08。ここではURLを保存し、ドメインだけを表示する）
  - Idempotency-Key（別タスク）、退会時の表示（「退会したユーザー」）
  - 最終的な画面デザイン

## 受け入れ条件
- [ ] 友達のここ暇と重なる時間で誘うと「あそぼ」、重ならなければ「ここどう？」になる。見せてもらっていない枠は判定に使わない
- [ ] 友達でない人・自分には送れない（友達でない人は、存在しない人と同じ404）
- [ ] 1日の送信が上限を超えると送れない
- [ ] 受け取った人は「行く」「今回は難しい」「この時間なら」で返答でき、行くと成立した予定が双方に出る
- [ ] 「この時間なら」には送信者が「決める」（成立）か「見送る」を選べる
- [ ] 期限を過ぎると返答できず、誰にも通知されない
- [ ] 断り・期限切れ・見送り・キャンセルが、赤やエラー色でなく静かに表示される。断りの理由は保存も表示もしない
- [ ] 成立した予定を「やっぱり難しい」でキャンセルできる
- [ ] 同時に返答しても、状態は1回しか進まない
- [ ] 他人のIDでは取得・更新できないテストがある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
