## 概要
価値の核の「暇がなくても誘える（ここどう？）」の入口が、友達タブ → 友達の詳細の奥にしかなかった。また「みんな」は、誰のここ暇も見えないと、友達がいても「友達を招待すると…」と出していた。「みんな」の一番上に、友達全員の顔を並べた「誰を誘う？」を出し、押すとその友達を入れた誘いの作成を開く。空の状態は友達の有無で分ける。API は変えない（画面だけ）。

## 決めたこと
1. **顔の列は友達全員。** ここ暇の有無・見せる／見せないで、出す・出さない・並び・印を変えない。並びは友達の一覧（T-02。友達になった日時の新しい順、同じなら友達の `id` の降順）のまま。読むのは今の `GET /api/v1/friends`（続きのページも最後まで。`everyFriendQuery`）だけ。
2. **押すと誘いの作成を、相手だけを入れて開く**（`/invites/new?friend=<id>`。友達の詳細の「誘う」と同じ）。日時は今の初期値（次の15分の区切りの1時間後から2時間）。「あそぼ」／「ここどう？」は今の作成画面のとおり、相手の見えている枠と重なるかで画面に出し、送った結果はサーバーの `kind` を正とする（T-04）。重ならなければ自動で「ここどう？」になる。
3. **空の状態は友達の有無で分ける。**
   - 友達がいて、見えているここ暇がない：顔の列と「暇な人いる？と募る」を出したまま、「まだ友達のここ暇はありません」と「ここ暇がなくても、上の顔から「ここどう？」と誘えます」。招待のボタンは出さない。顔の列が出ていない（友達の一覧を読み込み中・読めない）ときは、説明の「上の顔から…」は出さず、題だけにする。
   - 友達が0人：「まだ友達はいません」「友達を招待すると、ここに暇な時間が並びます」と、「友達を招待する」の1つのボタンだけ（顔の列・募るボタン・ここ暇の一覧・友達の行きたいの欄は出さない。募集は宛先が2人以上要るため）。押すと、友達タブと同じ招待リンクの発行のシート（`InviteLinkSheet`。「共有する」「LINEで送る」がある。T-28）を開く。
4. **ボタンの文言は「友達を招待する」にする**（issue の案は「LINE で招待を送る」）。「LINEで送る」は招待リンクを作ってから出すもので（T-28）、作る前の期間・人数の選択と、表示名が未設定のときの入力（T-02）を飛ばせないため、押してすぐ LINE を開くボタンにはしない。
5. **友達の詳細の「ここどう？と誘う」を「誘う」にする。** 重なれば「あそぼ」になるため。行き先は変えない。

## 振る舞い

### 「みんな」（`/`）の上から順の並び
- 友達が1人以上（または友達の一覧を読み込み中・読めない）：
  1. 「誰を誘う？」の節（友達の一覧が読めたとき）。見出し「誰を誘う？」（`h2`）と、友達の顔の列。
     - 1人ずつ、顔（`Avatar` の `l`）と、その下に表示名（長ければ省略。未設定は「名前未設定の友達」）。
     - リンクの読み上げの名前は「<表示名>を誘う」。行き先は `/invites/new?friend=<id>`。
     - 列は横にスクロールする（`overflow-x-auto`）。画面全体は横にスクロールさせない（列だけを画面の端まで広げる）。
  2. 友達の一覧が読めないとき：「友達を読み込めませんでした」と「もう一度」（静かな帯。T-11 の `LoadError`）。下の募るボタンとここ暇の一覧は出したまま。
  3. 「暇な人いる？と募る」（今のまま）。
  4. ここ暇の一覧（今のまま。読み込み中・読めない・回数の上限の表示も今のまま）。一覧は「みんなのここ暇」という名前の節にまとめる（顔の列と分けて読み上げ・テストで探せるように）。空なら決めたこと3。
  5. 友達の行きたいの欄（T-22。今のまま）。
- 友達が0人：決めたこと3。友達の一覧と、ここ暇の一覧は並列に読む（取得の連鎖を作らない）。友達の一覧が読めるまでは、友達がいるときの並びで出す。

### 友達の詳細（`/friends/{id}`）
- 誘いの作成へのボタンの文言を「誘う」にする（決めたこと5）。

### 置き場所

## 認可と秘匿
- 閲覧者IDの使い方：API を足さないので、今のまま（`GET /api/v1/friends` は閲覧者の友達だけを返す。T-02）。
- 他人のデータに届かないことの保証：今のまま。新しい API はないので、「他人のIDでは取得できない」テストは足さない（T-02 のテストのまま）。
- 区別させない応答：
  - 顔の列は友達の一覧だけから作り、ここ暇の一覧（`/friend-availabilities`）の結果で出す・並べる・印を付けることをしない。見せない相手・暇がない相手・ここ暇がある相手は、顔の列で同じ形になる（決めたこと1）。
  - API の応答の形は変えない。友達の一覧（`friendSchema`）には相手の公開設定は入っていない（`sharesMyAvailability` は自分の設定）。
  - 誘いの作成の「ここどう？」は、見えている枠だけで決まる（T-04 のとおり。見せない相手も暇がない相手も同じ `kokodou`）。

### E2Eテスト（対象にする利用者の流れ）
- [x] A と B が友達で、B にここ暇がない → A の「みんな」に「まだ友達のここ暇はありません」と募るボタン → 「誰を誘う？」の B の顔を押す → 相手が B で「ここどう？」の作成が開く → 送れる → B が受け取った誘いが「ここどう？」（`e2e/invites.spec.ts`）
- [x] 友達が0人 → 「みんな」に「まだ友達はいません」、募るボタンと顔の列はない → 「友達を招待する」で招待リンクの発行のシートが開き、リンクを作れる（`e2e/friends.spec.ts`）
- [x] 見せない相手（A）と、ここ暇がない相手（C）が、B の「誰を誘う？」にどちらも出る（`e2e/availability.spec.ts` の今のテストに足す）
- 今のテストの直し：友達の詳細の「ここどう？と誘う」を「誘う」に。「みんな」で相手の名前を探すテストは「みんなのここ暇」の中で探す。募るボタンのシートのテスト（`e2e/navigation.spec.ts`）は友達を作ってから開く。募集の宛先のチェックは、顔の列のリンク（「<表示名>を誘う」）と区別するためチェックボックスで探す（`e2e/broadcasts.spec.ts`）
- WebKit（`@iphone`）では新しいテストを回さない（シートの開き方は今の `@iphone` のテストで確かめている）
