# T-32 LINE ログイン

## 目的
LINE で届いた招待を LINE の中のブラウザで開いた人が、外に出ずにログインできるようにする。LINE ログインをログインの画面の最初のボタンにし、メールアドレスがない人でも通知と問い合わせが成り立つようにする。

## 関係する要件
- F-01（認証。LINE を足す。Google と LINE は別の利用者。#45）
- F-03（通知。メールアドレスがない人）、F-22（問い合わせ。返事の宛先）
- issue：pryusei/kokohima-app#180（親 #178）

## スコープ
- やること：
  - LINE ログイン（OIDC、通常のチャネル、scope は `openid`）を identity に足す。state・nonce・PKCE・結びつけ Cookie・完了コードは Google と同じ。IDトークンは LINE の verify で確かめ、こちらでもクレームを確かめる
  - ログインの画面と招待の受け口で、LINE を最初のボタンにする（Google は残す）。LINE の中のブラウザの帯の文を直す
  - メールアドレスがない人の通知・新しい端末のログイン・問い合わせの扱いと文言
  - 退会のログインし直しで LINE を使う
  - 偽の LINE（E2E）、単体テスト、E2E
  - プライバシー ポリシー・利用規約の改定（予告なし）。T-01・T-07・T-16・T-19・T-24・T-28・要求定義書を合わせる
  - 持ち主の作業の手順書（チャネルの作成・コールバック URL・公開・`wrangler secret put`）
- やらないこと（スコープ外）：
  - アカウントの統合、LINE の名前・アイコン・メールアドレスの取得
  - LIFF・ミニアプリ・Messaging API
  - 招待リンクの `openExternalBrowser=1` をやめること

## 受け入れ条件
- [x] ログインの画面と招待の受け口で、「LINEでログイン」が最初、「Googleでログイン」が次に出る
- [x] 「LINEでログイン」を押すと LINE の認可画面へ移り、戻ると名前の画面を経てログインできる。2回目は同じ利用者になる
- [x] state・nonce・PKCE・結びつけ Cookie と、IDトークンの発行者・宛先・期限・nonce を確かめ、どれかが違えばログインの失敗の画面に戻る
- [x] Google と LINE で入った人は別の利用者になる
- [x] メールアドレスのない人の新しい端末のログインは、メールを送らずお知らせ一覧に残る
- [x] チャネル ID かシークレットがない環境では、LINE のログインはログインの失敗の画面に戻り、何も書かない
- [x] 他人のIDでは取得できないテストがある
- [x] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（CI で確かめる）
- [x] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [x] typecheck・lint・関係するテストが通る
- [ ] 持ち主の作業（仕様書「10.」）を済ませ、実機で確かめる
