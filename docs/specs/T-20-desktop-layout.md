## 概要
- 今の画面は、どの幅でも `max-w-md`（448px）の1列で、PC のブラウザでは真ん中に細く出て、下のタブとシートも細いまま出る。
- 幅1024px以上のときだけ、左に固定のナビを置き、中身を広げ、シートを中央のダイアログにする。1023px以下は今のまま。
- 変えるのは `apps/web` の配置だけ。API・データ・画面の中身（文言・取得の流れ・URL）は変えない。

## API
変えない。新しい経路も作らない。

## データ
変えない（マイグレーションなし）。

## 振る舞い

### 画面の大きさの区切り（決定事項1）
- 区切りは1つだけ：幅1024px以上を「PC の配置」、1023px以下を「スマホの配置」（今のまま）にする。
- 判定は CSS のメディアクエリ（Tailwind の `lg:`、`min-width: 64rem`）だけで行う。User-Agent やタッチの有無では分けない。
  - 理由：同じ部品を同じ DOM のまま幅で見た目だけ変えると、幅を変えても URL・開いているシート・入力中の内容・フォーカスが失われない。
- JS で幅を読むところは、`window.matchMedia("(min-width: 64rem)")` を `useSyncExternalStore` で読む1つのフック（`apps/web/src/ui/useDesktop.ts`）にまとめる。`matchMedia` がない環境では「スマホの配置」とする。使うのは次の2つだけ（シートのつまみは CSS で隠す）：
  - ヘッダーの鐘と、左のナビのお知らせ・設定のどちらを描くか（同じリンクを2つ描いて CSS で隠すと、読み上げとテストで同じ名前のリンクが2つになるため）
  - 設定・お知らせの画面で左のナビを描くか
  - 画面の中身（各画面・シート・入力欄）は、幅で描き分けない

### 画面の枠（決定事項2）
- `TabScreen`・`SubScreen`（`apps/web/src/ui/Navigation.tsx`）を、PC の配置では次の形にする：

  | 場所 | PC の配置 | スマホの配置（今のまま） |
  | --- | --- | --- |
  | ナビ | 画面の左に固定（幅240px、`bg-surface`、右に `border-line`）。上から「ここ暇」の名前、みんな・ここ暇・誘い・友達、区切りの線、お知らせ（未読の数）・設定 | 下のタブ（4つ）とヘッダーの鐘 |
  | ヘッダー | 画面の名前だけ（鐘は出さない。お知らせはナビにある） | 画面の名前と鐘 |
  | 中身 | ナビの右の残りの幅の中で、最大幅 `max-w-3xl`（768px）、左寄せで左右の余白24px | `max-w-md` の1列 |
  | 設定・お知らせ（`SubScreen`） | ナビを出し、「戻る」も今のまま出す | 戻るだけ、下のタブなし |

- ナビは1つの `<nav aria-label="タブ">` のまま、幅で見た目だけ変える（スマホの配置で下のタブ、PC の配置で左のナビ）。お知らせ・設定の2つのリンクと上の「ここ暇」の名前は、PC の配置でだけ描く（`useDesktop`）。
  - 今いる画面のリンクに `aria-current="page"`。お知らせ（`/notifications`）・設定（`/settings` とその下）も同じ。
  - 未読の数と読み上げは、鐘と同じ `unreadLabel` を使う。
- ナビのリンクは高さ44px以上。今いる画面は `bg-lamp-soft` と `text-ink`、それ以外は `text-ink-muted`（下のタブの灯りの点と同じく、黄色は今いる場所の印にだけ使う）。マウスを乗せたら `bg-surface-sunken`。
- 一覧の中身（カードの並び）は1列のまま広げる。カードを2列にはしない（スコープ外）。
- ログイン（`/login`）・招待リンクの受け口（`/invite`）・ログインの完了・プライバシー ポリシー・利用規約・読み込み中と接続できない画面は、PC の配置でもナビを出さず、今のまま中央に置く。

### シート（決定事項3）
- `BottomSheet`（`apps/web/src/ui/BottomSheet.tsx`）は、PC の配置では画面の中央のダイアログで出す：
  - 幅 `max-w-lg`（512px）、高さは画面の88%まで（超えたら中をスクロール）、四隅を `rounded-sheet`、影は `shadow-float`。
  - 上のつまみは出さない。右上の「閉じる」のボタン（✕の印）は T-11 でどの幅でも出すので、そのまま使う。下に引いて閉じる動きは PC の配置では効かない。
- ほかの振る舞いは T-11 のまま変えない：URL、後ろのタブ（`behind`）、Esc、後ろの暗い部分、フォーカスの閉じ込めと戻し、`#root` の `inert`、送信中に閉じたときの扱い。
- `prefers-reduced-motion` では、出るときの動きを止める（今と同じ）。
- 開いたボタンは、シートを描いた時点で覚える（effect の時点ではない）。URL を持つシートは、後ろのタブを同じ描画で `inert` にするので、effect の時点ではブラウザがフォーカスを body に移していて、閉じたときに戻す先がわからなかった（スマホの配置でも起きていた。T-11 の「閉じたら開いたボタンにフォーカスを戻す」を満たすために直した）。

### 幅を変えたとき
- 幅をまたいで変えても、DOM を作り直さない（同じ部品の見た目だけ変える）ので、URL・開いているシート・入力中の内容・フォーカスはそのまま。

## 認可と秘匿
- 閲覧者IDの使い方：変えない（API を変えない）。
- 他人のデータに届かないことの保証：変えない。画面に出す項目も増やさない。
- 区別させない応答（見せない／暇がない／募集の応答者など）：変えない。PC の配置で出す項目は、スマホの配置と同じ。

### E2Eテスト（対象にする利用者の流れ）
- 今の E2E の `chromium` は `Desktop Chrome`（1280×720）で回っているため、PC の配置にすると今の「下のタブ」の流れが合わなくなる。次のように分ける：
  - `mobile`：今の E2E 全部を、幅390×844（`devices["iPhone 13"]` の大きさ、ブラウザは Chromium）で回す。中身は変えない
  - `desktop`：`Desktop Chrome`（1280×720）で、`e2e/desktop.spec.ts` だけを回す
- [x] PC：左のナビで みんな → ここ暇 → 誘い → 友達 → お知らせ → 設定 と移れ、`aria-current` が移る。下のタブは見えない
- [x] PC：誘いの一覧のカードから詳細が中央のダイアログで開き、Esc で閉じると誘いの画面に戻り、カードにフォーカスが戻る。「閉じる」のボタンでも閉じる
- [x] PC：主な画面（4つのタブ・お知らせ・設定・ログイン）で、`document.documentElement.scrollWidth` が画面の幅を超えない
- [x] 誘いの作成のシートに入力したまま、画面の幅を390pxと1280pxの間で変えても、入力した内容とシートが残る
