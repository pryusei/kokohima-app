## 前提

### デザインの決まり（デザインシステムの README の要約）
- 色・文字・余白・角丸・影は、SmartHR UI（MIT）の既定のテーマの値に近づけた。ただし、SmartHR の危険の赤とブランド色（ターコイズ）は使わない。
- 灯りの黄色（`lamp`）は、自分と重なるここ暇の枠・ここ暇を作るボタン・未読の印にだけ使う。成立は緑（`meet`）だけ。
- 断り・期限切れ・見送り・締め切り・やっぱり難しい・失敗は、`quiet-bg`・`quiet-ink` の静かな表示にする。赤やエラー色、警告の印、取り消し線を使わない。
- 書体は端末の標準の書体（system-ui、ヒラギノ角ゴ、Noto Sans JP）。Web フォントは読み込まない。
- 押せる部品は44px以上。フォーカスは `surface` の2pxの隙間の外に `focus` の2pxの輪。`prefers-reduced-motion` では動きを止める。

## 振る舞い

### トークンとテーマ（決定事項1）
- `apps/web/src/index.css` に、デザインシステムの `tokens.json` の値を CSS 変数で置く。
  - ライトの値を `:root` に置く。
  - 夜の値を `@media (prefers-color-scheme: dark)` の中に置く。
- Tailwind v4 の `@theme` で、CSS 変数を Tailwind の名前に結ぶ（`bg-surface`、`text-ink-muted`、`rounded-l` など）。
- Tailwind の既定の色の名前（`slate`・`gray`・`zinc`・`neutral`・`stone`・`red`・`orange`・`amber`・`yellow`・`lime`・`green`・`emerald`・`teal`・`cyan`・`sky`・`blue`・`indigo`・`violet`・`purple`・`fuchsia`・`pink`・`rose`）は使わない。lint で禁止はせず、単体テストでソースを検査する（テスト計画）。
- テーマを手で切り替える設定は作らない（スコープ外）。

### 共通の部品（決定事項2）
- 今の `apps/web/src/components/Nav.tsx`（仮のナビ）は、`TabBar` と `Header` に置き換えて消す。`Link` はそのまま使う。
- `apps/web/src/ui/` に置く。デザインシステムのコンポーネントと同じ名前にする：
  - `Button`、`Badge`、`AvailabilityChip`、`SlotChips`、`InviteCard`、`BroadcastCard`、`ResponseButtons`、`HeadCount`、`LinkCard`
  - `NotificationRow`、`TabBar`、`Header`、`BottomSheet`、`Switch`、`Avatar`、`Toast`、`EmptyState`、`StatusStates`
  - 実装の置き場所：`Header` は `ui/Navigation.tsx` の `TabScreen`（鐘つき）と `SubScreen`（戻るつき）、`StatusStates` は `ui/feedback.tsx` の `Loading`・`LoadError`・`OfflineBanner`、`SlotChips` は `ui/form.tsx` の `Chip`・`ChipRow`。
- 状態ごとの見た目は、真偽値の props を増やさず、`variant`（`"meet" | "pending" | "lamp" | "quiet"`）などの1つの値で渡す（`vercel-composition-patterns`）。
- 誘いの状態 → バッジの対応は、`apps/web/src/invitations/format.ts` に関数を1つだけ置く（`statusTone`）：
  - `confirmed`（成立）→ `meet`
  - `pending`（返事待ち）→ `pending`
  - `counter_proposed`（この時間なら）→ `lamp`
  - `declined`・`expired`・`skipped`・`cancelled` → `quiet`
- 募集も同じ：`decided` → `meet`、`open` → `pending`（宛先の人が応じたあとは `lamp`）、`expired`・`closed` → `quiet`。
- 今の `statusClass`・`broadcastStatusClass` は、この関数に置き換える。

### 画面のつながり（決定事項3）
- 下のタブは「みんな（`/`）・ここ暇（`/availability`）・誘い（`/invites`）・友達（`/friends`）」の4つ。今いるタブに `aria-current="page"`。
- お知らせ（`/notifications`）はタブから外す。各タブのヘッダーの鐘のボタンから開く。未読があれば数を出す。
  - 0のときは数を出さない。`aria-label` は「お知らせ」。
  - 1〜98のときは数を出す。`aria-label` は「お知らせ N件の未読」。
  - 99のときは「99+」と出す。API の未読の数は99で頭打ちにしている（`UNREAD_CAP`、`unreadCountSchema` の `max(99)`）ため、99は「99件以上」を表す。`aria-label` は「お知らせ 99件以上の未読」。
- 下から出るシートで開く画面と、その後ろに出すタブ：

  | URL | シート | 後ろのタブ |
  | --- | --- | --- |
  | `/invites/new` | 誘いの作成 | みんな |
  | `/broadcasts/new` | 募集の作成 | みんな |
  | `/invites/{id}` | 誘いの詳細（受信・送信） | 誘い |
  | `/broadcasts/{id}` | 募集の詳細（募集者・宛先の人） | 誘い |
  | `/meetups/{id}` | 成立した予定 | 誘い |
  | `/friends/{id}` | 友達の詳細 | 友達 |

  - URL は今のまま変えない（お知らせ・メール・E2E から直接開ける）。
  - ここ暇の追加・くり返しの追加・招待リンクの発行は、URL を持たないシートにする（今は画面の中のフォーム）。
- シートを閉じる操作：つまみを下に引く、後ろの暗い部分を押す、`Esc`。
  - 閉じると、アプリの中から開いたときだけ1つ前の画面に戻る（`history.back()`）。それ以外（メール・お知らせのプッシュ・URL の直接入力で開いたとき、再読み込みのあと）は、後ろのタブの URL へ移る（`navigate(..., { replace: true })`）。
  - 後ろに出すタブ：アプリの中から開いたシートは、開いたときのタブ（`?tab=` も）のまま後ろに出す（`history.state` の `behind`）。シートからシートを開いたときは前の `behind` を引き継ぐ。外から直接開いたときは、上の表のタブ。後ろのタブが変わらないので、閉じたときに開いたボタンへフォーカスを戻せる。
- シートは body の直下に描き、開いている間はアプリの本体（`#root`）を `inert` にする（URL を持たないシートでも、後ろに Tab で入れない）。
- Esc は日本語入力の変換を取り消すときには効かない。暗い部分は、押し始めも離したのも暗い部分のときだけ閉じる。
- 誘い・募集の作成の送信中にシートを閉じたら、成功しても詳細へ移らない。
- - 「アプリの中から開いた」の判定：`apps/web/src/router.ts` の `navigate` が `pushState` するときに `history.state` に印（`{ inApp: true }`）を付け、シートを閉じるときにその印があるかを見る。`history.length` は使わない（タブ全体の履歴を数えるので、外から直接開いたときも「1つ前がある」になり、`history.back()` でアプリの外へ出てしまう）。
  - 閉じるときに確認のダイアログは出さない。
- シートを開いている間は、シートの中にフォーカスを閉じ込める。閉じたら、開いたボタンにフォーカスを戻す。
- 設定は友達タブの「アカウント」の節から開く。

  | URL | 画面 | 中身 |
  | --- | --- | --- |
  | `/settings` | 設定のトップ | 新しい画面。表示名と、各設定への入口 |
  | `/settings/calendar` | カレンダー連携 | 今のまま |
  | `/settings/presets` | 時間帯プリセット | 今のここ暇タブの「プリセットの境界の変更」を移す |
  | `/settings/notifications` | 通知の設定 | 今のまま |
  | `/settings/account` | アカウント | 今の友達タブの表示名の設定（`PATCH /me`）・ログアウト・全端末ログアウトを移す |

  - 設定の画面は、左上の「戻る」で設定のトップへ、設定のトップからは友達タブへ戻る。

### オフライン（決定事項4）
- `navigator.onLine` と `online`・`offline` のイベントで判定する。オフラインの間は、ヘッダーの下に「オフラインです。つながると最新の内容になります」の帯を出す。
- オフラインの間は、送る操作（作成・返答・応じる・設定の保存、取り消し・削除・無効にする・.ics の発行、すべてのスイッチ）を押せなくする。スイッチは楽観的更新なので、押せると画面だけが変わって送られないことがあるため。読むだけの画面は、TanStack Query がすでに持っているデータをそのまま出す。
- ログアウト・全端末ログアウトも、オフラインの間は押せなくし、ボタンの下に「オフラインの間はログアウトできません」と出す。今の `AuthProvider` は 204 のときだけログアウトの状態にするので、オフラインで押しても何も起きず、利用者には理由がわからないため。
- オフラインでも読めるようにするキャッシュ（Service Worker のキャッシュ、データの端末への保存）はしない。
  - 理由：他人の暇・誘いの中身を端末に残さないため。アクセストークンをメモリにだけ置く決まり（CLAUDE.md）とも合わせる。
- つながったら、TanStack Query の `onlineManager` に任せて読み直す。

## 認可と秘匿
- 閲覧者IDの使い方：変えない（API を変えないため）。
- 他人のデータに届かないことの保証：変えない。シートの後ろに出すタブの画面も、今と同じ閲覧者の権限で読む。
- 区別させない応答（見た目でも区別させない）：
  - 見せない相手と暇がない相手は、どちらも「みんな」と友達の詳細に何も出さない（今と同じ）。灰色の枠などで「見せない」を示さない。
  - 募集の宛先の人には、期限後は決まったか期限切れかを区別せず「締め切りました」を、同じ `quiet` のバッジで出す。応じた人がいるかを、色・形・数で示さない。
  - 自動で断った誘い（カレンダーの予定と重なった）は、送った人には手で断ったときと同じ「今回は難しいみたい」と `quiet` のバッジで出す。
- 端末に残すもの：増やさない（オフラインのキャッシュをしない）。

## 決定事項（仕様書PRのレビューで合意する）
1. 色・文字・余白は、デザインシステム「ここ暇」のトークンを CSS 変数にし、Tailwind v4 の `@theme` で使う。夜のテーマは端末の設定に合わせる。（提案）
