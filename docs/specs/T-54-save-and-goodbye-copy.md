## 概要
表示名と時間帯プリセットの「保存しました」は、ボタンの下の小さな灰色の文字だけで、暗い画面では特に気づきにくい。ボタンも押したあとと前とで見た目が同じで、変えていなくても押せる。そこで、変えるまでは押せないようにし、保存できたらボタンそのものを約2秒「✓ 保存しました」に変える。あわせて、退会のあとのログイン画面の「退会しました。」を、感謝の一文に変える（持ち主の依頼）。

## 振る舞い

### 保存のボタン（表示名・時間帯プリセット）
- 対象：設定のアカウント（`/settings/account`）の表示名の「保存する」、設定の時間帯プリセット（`/settings/presets`）の「時間帯を保存」。名前の画面の「これで始める」（T-31）も同じ部品を使う（保存すると画面ごと切り替わるので、見た目の変化は出ない）。
- 2つの画面で同じ部品にする：`apps/web/src/ui/SaveButton.tsx` の `SaveButton`（ボタン）と `useSaveState`（状態）。ボタンの状態は1つの値（`unchanged`・`changed`・`saving`・`saved`）で渡す（`vercel-composition-patterns`）。
- 押せる・押せない：
  - 入力が今の保存済みの値と同じあいだは押せない（無効）。変えると押せる。元の値に戻すと、また押せない。
  - 保存済みの値は、画面を開いたときの値。保存できたら、API が返した値に置き換える。
  - 表示名は、サーバーと同じ正規化（NFC と前後の空白を除く）をしてから比べる。前後に空白を足しただけでは押せない。空白だけのあいだも押せない（T-31 のまま）。
  - 時間帯プリセットは、昼・夕方・夜の開始と終了の6つをすべて比べる。
  - 送信中は押せない（今のまま）。オフラインのあいだは押せない（T-11「オフライン」。`SendButton` を使う）。
- 保存できたら：
  - ボタンそのものが「✓ 保存しました」に変わる。色は成立の系統のトークン（枠 `border-meet`、地 `bg-meet-soft`、文字 `text-meet-ink`）。主ボタンの青より静かで、灰色の無効のボタンとは見分けられる。
  - このあいだボタンは押せない（変えていないので）。押せないあいだの灰色（`disabled:` の色）はこの見た目にだけ付けない。Tailwind v4 では `disabled:` の色が地の色より後に出て必ず勝つため、`Button` の variant `saved` は押せないときの色を持たない。
  - 約2秒（`SAVED_MS` = 2000ミリ秒）たったら、元の文言（「保存する」「時間帯を保存」）と色に戻り、押せない状態になる。
  - 2秒のあいだに入力を変えたら、すぐに押せるボタン（元の文言と色）に戻る。
  - 「✓」は読み上げない（`aria-hidden`）。ボタンの外に見えない `role="status"` を置き、保存できたあいだだけ「保存しました」を入れて読み上げる。ボタンの下の灰色の「保存しました」はなくす。
  - 動き（アニメーション・トランジション）は付けない。色と文字が切り替わるだけ。`prefers-reduced-motion` でも同じ（このタスクで足す動きがないため。トランジションを止める index.css の全体の指定は今のまま）。
    - （T-56 で変わる：送信中（`saving`）は灰色にせず元の色のまま `opacity: .7`（`--duration-fast` の transition）で「保存しています…」にし、`disabled` ではなく `aria-disabled` にする。✓ の部分は送る操作のボタンと同じ部品（`DoneLabel`）にする。「✓ 保存しました」の2秒と色はこの仕様書のまま。docs/specs/T-56-motion.md「M-14」）
- 保存できなかったとき：今の表示のまま（ボタンの下に静かな文言。赤やエラー色を使わない）。ボタンは押せるまま（入力は保存済みの値と違うので）。

### 退会のあとのログイン画面
- `/login?withdrawn=1` に出す文を「退会しました。」から「今まで使ってくれてありがとう。またいつでも待ってるね。」に変える。
- 表示は今のまま：静かな面（`bg-surface-sunken`）、`role="status"`、赤を使わない。表示名は出さない（トークンとキャッシュを消したあとなので、もともと持っていない）。
- 退会でデータは消えるので、「戻ってきたら続きから」のような、事実と違うことは書かない。
