# T-57 成立した予定から Google カレンダーに入れる

## 目的
成立した予定の画面に「カレンダーに追加（.ics）」しかなく、持ち主から「Googleカレンダーに追加が出てこない」と指摘があった。連携している人の予定は裏で自動で「ここ暇」カレンダーに入る（T-06）が、画面のどこにも出ていない。予定の画面に、閲覧者の連携の状態に応じた1行またはボタンを出し、連携していない人はその場から連携できるようにする。

## 関係する要件
- F-13、F-02、要求定義書「デザイン原則」
- 仕様書：docs/specs/T-57-meetup-google-calendar.md
- T-06（docs/specs/T-06-calendar.md）、T-04・T-05（成立した予定の詳細）、T-43（成立の演出）、T-11（デザイン）、T-56（結果の帯・送信中のボタン）

## スコープ
- やること：
  - 成立した予定の詳細と成立の演出の中の .ics の場所を、カレンダーへの入れ方の欄（`MeetupCalendarActions`）にする
  - 連携中：「連携中なので、Googleカレンダーの『ここ暇』に自動で入ります」の静かな1行
  - 連携していない：「Googleカレンダーに自動で入れる」→ Google の同意画面 → この予定の画面に戻る（連携の開始に任意の `meetupId`、`calendar_oauth_states.return_meetup_id`）
  - もう一度連携が要る：静かな1行と設定へのリンク
  - Google と並ぶときの .ics を「ほかのカレンダーに追加（.ics）」にする
  - 単体テスト・E2E、T-06・T-43・T-04 の仕様書を直す
- やらないこと（スコープ外）：
  - 予定ごとに書けたかを保存して「入っています」と言い切ること
  - 「Googleカレンダーで見る」のリンク
  - 予定の画面からの連携の解除、Apple カレンダー（T-09）

## 受け入れ条件
- [ ] 連携の状態ごと（連携中・していない・もう一度連携が要る）と、出さないとき（取り消し・抜けた・終わった予定、状態を読めないとき）の表示が仕様書のとおり
- [ ] 連携していない人が予定の画面から連携すると、同じ予定の画面に戻り、結果の帯が出る
- [ ] 戻り先がオープンリダイレクトにならず、`meetupId` で予定の有無を確かめられない
- [ ] 赤・エラー色を使わない。トークンと `apps/web/src/ui/` の部品を使う
- [ ] 他人のIDでは取得できないテストがある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストを追加・更新した
- [ ] 仕様書とコードに齟齬がない（T-06・T-43・T-04 も直した）
- [ ] typecheck・lint・関係するテストが通る
