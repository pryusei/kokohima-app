# T-06 カレンダー連携（Google）と .ics

## 目的
Googleカレンダーと連携した人が、カレンダーの空きからワンタップでここ暇を作れ、実予定が入ったここ暇が自動で取り消され、成立した予定が自分のカレンダーに入るようにする。連携しない人（Appleの人を含む）も、成立した予定を .ics でカレンダーに追加できるようにする。

## 関係する要件
- F-02：カレンダー連携（このタスクはGoogleだけ。Apple CalDAVは T-09）
- F-03：カレンダーの空きを候補表示し、ワンタップで設定
- F-06：実予定が入ったらここ暇を自動で取り消す（本人への通知は T-07）
- F-13：成立した予定をカレンダーに登録（Googleへの自動登録と、全員向けの .ics）
- NF-02・NF-03：outbox から Queues 経由で非同期に処理し、失敗時は再試行する
- NF-04：認証情報は Secrets の鍵でアプリ側暗号化して保存する
- NF-06：プロバイダを抽象化する（Apple・Outlookを後で足せる形）
- 要求定義書「状態遷移とビジネスルール」（自動取り消しと、未返答の誘いの自動の「今回は難しい」）、セキュリティ設計の残りの論点「Googleの具体的なスコープの確定」

## スコープ
- やること：
  - Googleカレンダーの連携・連携解除（ログインとは別の許可。トークンは暗号化して保存し、解除時はGoogle側でも失効させる）
  - カレンダーの空きから、時間帯プリセットの候補を出す（ワンタップで T-03 のここ暇を作る）
  - 定期的に埋まりを確かめ、新しく入った実予定と重なるここ暇を自動で取り消す（くり返しはその日だけ外す）。その枠への未返答の誘いを自動で「今回は難しい」にする
  - 成立した予定を、連携している参加者のGoogleカレンダー（アプリが作る「ここ暇」カレンダー）に書き込み、キャンセル・抜けたときに消す
  - 成立した予定の .ics のダウンロード（連携の有無にかかわらず、参加者全員）
  - outbox を Queues に流す仕組み（Cron で取り出し、Queue の consumer で処理）と、wrangler・Terraform の設定（apply・deploy はしない）
  - 画面（仮）：設定のカレンダー連携、ここ暇タブの「カレンダーの空き」、予定の詳細の「カレンダーに追加」
- やらないこと（スコープ外）：
  - Apple CalDAV（T-09。NF-10 の技術検証を先に行う）、Outlook
  - 通知（T-07。自動取り消しの本人への通知もここ）
  - Googleの変更通知（Webhook）。定期の確認で代える
  - メインのカレンダー以外の埋まりの確認
  - 最終的な画面デザイン

## 受け入れ条件
- [ ] 設定からGoogleカレンダーと連携でき、連携の状態が見える。解除するとトークンが消え、Google側でも失効する
- [ ] 連携した人のここ暇タブに、埋まりと重ならない時間帯プリセットの候補が出て、ワンタップでここ暇になる
- [ ] 連携後に新しく入った実予定と重なるここ暇が自動で取り消され、その枠への未返答の誘いは、手で断ったときと区別できない「今回は難しい」になる
- [ ] 成立した予定が、連携している参加者のGoogleカレンダーに入り、キャンセル・抜けたときに消える
- [ ] 参加者は、成立した予定を .ics でダウンロードできる。参加者でない人・抜けた人は404
- [ ] 予定のタイトル・場所・参加者を、Googleから読まない・保存しない（APIの呼び出しが空き／埋まりだけであることをテストで確かめる）
- [ ] トークンは暗号化して保存され、ログ・エラーに出ない
- [ ] Googleが失敗・遅延しても、ここ暇と誘いの機能は止まらない
- [ ] 他人のIDでは取得・更新できないテストがある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
