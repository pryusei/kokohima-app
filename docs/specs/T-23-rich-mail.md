# T-23 仕様書：リッチなHTMLメール

- 状態：下書き
- タスク票：なし（利用者の依頼から起こした。必要なら docs/tasks/T-23-rich-mail.md を足す）
- 関係する要件：F-06、F-08、NF-02、セキュリティ設計（通知メールにログイン用のリンクを入れない）。T-07 の「メールの中身」を置き換える

## 概要
T-07 のメールはテキストだけで、受信トレイで読みづらく「ここ暇」らしさもない。ロゴ・色つきのヒーロー・ボタンを持つHTMLメールにする。送る内容（種類の短い説明だけ。相手の名前などは入れない）と、送る条件・上限は T-07 のまま変えない。

## API
追加・変更なし。Resend への送信（`POST https://api.resend.com/emails`）の本文に `html` を足す。`text` も引き続き送る（HTMLを表示しないメールソフト用。multipart/alternative）。

## データ
なし。マイグレーションなし。

## 振る舞い

### 構成
`apps/api/src/notification/domain/mail.ts` の `mailFor` が `{ subject, text, html }` を返す。HTMLは `domain/` の純粋な関数で組み立てる（テンプレートエンジンやライブラリは足さない）。

上から次の順に並べる。
1. プレヘッダー（受信トレイの一覧に出る1文。種類の短い説明）
2. ロゴ（文字の「ここ暇」）
3. カード：ヒーロー（絵文字・見出し・小さな1行）→ 本文 → ボタン「アプリを開く」→ 区切り線 → 注意書き
4. フッター（自動送信であること・心当たりがなければ破棄すること・`APP_ORIGIN`）

### 種類ごとの見た目
- 見出しは T-07 の `SUMMARY`（「誘いが届きました」など）をそのまま使う。絵文字とヒーローの色は種類ごとに決める。
- 本文の1文目は「アプリを開いて、お知らせを確認してください。」。種類ごとの補足は1文まで。
- 断り・見送り・取り消し・期限切れ・連携切れ（`invite_declined`・`invite_skipped`・`meetup_cancelled`・`meetup_left`・`availability_cancelled`・`calendar_reauth`）は、赤・警告の色と警告の絵文字を使わない。静かな色（quiet）のヒーローにする（CLAUDE.md の UI の決まり）。
- 新端末のログイン（`new_login`）は、本文に端末の要約とログインの日時を表で入れる。心当たりがなければ「すべての端末からログアウト」を押すよう書く。止められないこと（注意書き）は種類によらず入れる。

### 色
- 色は `apps/web/src/index.css` のトークンの値と合わせる（`--kh-surface`・`--kh-ink`・`--kh-ink-muted`・`--kh-lamp`・`--kh-meet`・`--kh-quiet-bg` など）。メールでは CSS 変数が使えないので、16進の値を `domain/mail-theme.ts` の1か所にまとめ、トークンを変えたら一緒に直す（単体テストで index.css の値と一致することを確かめる）。
- 依頼で示されたサンプルの珊瑚色（`#ff6b4a`）は、アプリのトークンにないので使わない。ボタンは `--kh-action`、強調は `--kh-lamp`、成立など良い知らせは `--kh-meet` を使う。
- ダークモード：`@media (prefers-color-scheme: dark)` でトークンのダーク値に切り替える。`<meta name="color-scheme" content="light dark">` を置く。

### メールソフトの互換性
- レイアウトは `<table role="presentation">`、スタイルはインライン。`<style>` は、ダークモードと狭い画面（幅620px以下）の上書きだけに使う。
- 幅は600px。ボタンは `<a>` を使った角丸の「ボタンに見えるリンク」（画像にしない）。
- 画像は使わない（読み込みの許可を求められる・追跡に使われるため）。絵文字と文字だけで作る。
- フォントは `-apple-system, 'Hiragino Sans', 'Noto Sans JP', Meiryo, sans-serif`。
- `lang="ja"`。リンクの文字は「アプリを開く」とし、ボタンが開けない場合のために URL を文字でも書く。

### 変えないこと（T-07 のまま）
- 差出人・宛先・件名（「ここ暇：新しいお知らせがあります」「ここ暇：新しい端末でログインがありました」）。
- 本文に相手の名前・ひとこと・エリア・予定の時刻を入れない（決定事項6）。
- リンクは `APP_ORIGIN` のトップだけ。ログイン用のトークンつきURL、パラメータ、トラッキング用のURLを入れない。
- 開封・クリックの計測、`List-Unsubscribe` はしない。
- 冪等キー、送る条件、1日の上限、失敗の扱い。

### HTMLの安全
- 差し込む値は、新端末のログインの端末の要約（`deviceSummary`）とログインの日時だけ。端末の要約はユーザーエージェント由来なので、必ずHTMLエスケープして入れる（`& < > " '`）。
- `APP_ORIGIN` も同じ関数でエスケープして `href` に入れる。`https:` で始まらない値（開発用の `http://localhost` を除く）は入れない。
- テンプレートは外から文字列を足す口を持たない（種類は `NotificationKind` の固定の表だけで決める）。

## 認可と秘匿
- 閲覧者IDの使い方：メールの宛先は T-07 のまま `getNotificationAddress(userId)`。この仕様でデータの取得は増えない。
- 他人のデータに届かないことの保証：HTMLに入れる値は、その利用者自身のお知らせの `kind`・`device`・`createdAt` だけ。
- 区別させない応答：変更なし（メールの種類の説明だけで、相手の名前・友達関係・公開設定を表す項目を入れない）。
- ログ：HTML・本文はログに出さない（T-07 のまま）。E2E の偽のメールの表は変えない（宛先・件名・`text` のまま。HTMLは単体テストで確かめる）。

## テスト計画

### 単体テスト（実装PRで必須）
- [ ] 全13種類で、`html` が `<!DOCTYPE html>` で始まり、`lang="ja"` と `color-scheme` を持ち、`text` と同じ種類の説明の文を含む。
- [ ] 全種類のHTMLに、相手の名前・ひとこと・エリアに当たる項目がない。リンクは `APP_ORIGIN` のトップだけ（`href` を全部取り出して確かめる）。
- [ ] 断り・見送り・取り消し・期限切れ・連携切れのHTMLに、赤系の色（トークンにない色）が入らない。使う色はすべて `mail-theme.ts` の値のどれか。
- [ ] `mail-theme.ts` の値が `apps/web/src/index.css` のトークンと一致する。
- [ ] 新端末のログイン：端末の要約に `<script>`・`"`・`&` を入れてもエスケープされる。日時が利用者のタイムゾーンで入る。
- [ ] `APP_ORIGIN` が `https:` でない（`javascript:` など）ときは `href` に入れない。
- [ ] `sendMail` が `html` と `text` の両方を JSON で送る。
- [ ] 既存の通知の単体テスト（件名・本文・冪等キー・上限）が、そのまま通る。

### E2Eテスト（対象にする利用者の流れ）
- 対象なし。メールの見た目はブラウザの画面ではなく、既存の E2E（T-07「誘いのお知らせ（メール）」「新端末のログイン」）が偽のメールの到着を確かめている。見た目の確認は、下の「確認事項」の手動の確認で行う。

## スコープ外
- 画像・ロゴ画像・アニメーション。
- メールの文面の多言語化。
- 開封・クリックの計測、`List-Unsubscribe`、メールから設定を開くリンク。
- 相手の名前・誘いの内容をメールに入れること（T-07 決定事項6を変えない）。
- 送る条件・上限・チャネルの切り替えの変更。
- Outlook のデスクトップ版（Word エンジン）での完全な再現。崩れても読めて、ボタンのリンクが押せればよい。

## 確認事項（合意前に解消する）
- 色：サンプルの珊瑚色ではなく、アプリのトークン（ランプの黄・ミートの青緑・アクションの青）に揃える案でよいか。サンプルの色に寄せたい場合は、先にデザイン（T-11）のトークンを変える。
- 種類ごとの絵文字の割り当て（案：誘い 💌、募集 📣、成立 🎉、友達 🙌、取り消し・見送り・連携切れ 🌙、新端末のログイン 🔔）。
- 手動の確認：実装PRで、Gmail・iOS メール・Apple の中継メールの実機で見た目を確かめる（Resend のテスト送信）。結果は実装PRの説明に書く。
