# T-02 友達と招待リンク

## 目的
招待リンクで友達を追加・解除でき、友達ごとに「自分の暇を見せる／見せない」を選べるようにする。以降の誘い・ここ暇のAPIが使う「友達関係」と「公開設定」の土台を作る。

## 関係する要件
- F-07：公開範囲（友達ごとに見せる／見せない。初期値は「見せる」）
- F-08：友達追加（期限と人数上限つきの招待リンク。開いてログインすると即友達。友達追加時に通知し、通知から公開をオフにできる）
- F-09：友達解除（静かに解除。通知なし。ブロックなし。発行者のリンクを再度開けば友達に戻る）
- 要求定義書「残りの論点」：招待リンクの有効期限と人数上限のデフォルト値、招待リンクのトークン設計
- 要求定義書「受容したリスク」：リンクを開いた人は即友達になる

## スコープ
- やること：
  - 招待リンクの発行（期限・人数上限を選ぶ）、自分の有効なリンクの一覧、無効化
  - 招待リンクの受け口（未ログインでも発行者の表示名がわかる。ログイン後に友達になる）
  - 友達一覧、友達の解除（相手に通知しない）
  - 友達ごとの「自分の暇を見せる」の切り替え（保存のみ。ここ暇への適用はT-03）
  - 友達が増えたときのイベント（`FriendshipEstablished`）を outbox に書く
  - 画面（仮）：招待リンクの受け口、友達タブ（一覧・切り替え・解除・リンク発行）
- やらないこと（スコープ外）：
  - 通知の送信（通知タスクで outbox のイベントを使う）
  - ここ暇の表示への公開設定の適用（T-03）
  - 監査ログ（公開設定の変更の記録）、ブロック、退会
  - 最終的な画面デザイン

## 受け入れ条件
- [ ] 招待リンクを発行すると、期限と人数上限つきのURLが一度だけ表示される。D1にはトークンのハッシュだけが保存される
- [ ] 別のユーザーがリンクを開いてログインし、発行者の表示名を確かめて「友達になる」を押すと、双方の友達一覧に相手が出る（仕様書の決定事項8）
- [ ] 期限切れ・人数上限に達した・無効化したリンクでは友達になれず、どれも同じ表示になる
- [ ] すでに友達の人がリンクを開いても、人数が消費されない
- [ ] 友達を解除すると、双方の一覧から消え、相手には通知されない。発行者のリンクを再び開けば友達に戻る
- [ ] 「自分の暇を見せる」を切り替えると保存され、解除して友達に戻っても設定が残る
- [ ] 他人のリンクの無効化、友達でない人の解除・公開設定の変更は、存在しない場合と同じ404になる
- [ ] 他人のIDでは取得・更新できないテストがある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
