# T-17 古いデータの掃除と保持期間

## 目的
終わった誘い・募集・予定、期限の過ぎた招待リンク、過去のくり返しの例外を、決めた期間のあとに毎分の掃除で消す。あわせて、表ごとの保持期間を一覧にする。ログインしていない人の連携では、カレンダーの確認を止める。

## 関係する要件
- 要求定義書「AI時代の攻撃を前提にした運用」：保存するデータを減らす
- NF-08（成立数などの集計）：今は記録を残さない（#46 で集計を作るときに決める）
- issue：pryusei/kokohima-app#38（古いデータの掃除と保持期間）の残り。済んだ分は T-12 データの増加（outbox・ここ暇）、#82（セッション）など

## スコープ
- やること：
  - 表ごとの保持期間の一覧（済んだものも参照として載せる）
  - 終わった誘い・募集・成立した予定を、終わってから30日で消す（利用者と決めた）
  - 期限から30日を過ぎた招待リンクを消す
  - 過去の日付のくり返しの例外を消す
  - 有効なセッションがない人の、カレンダーの定期の確認を止める（利用者と決めた。次にログインしたら再開）
- やらないこと（スコープ外）：
  - 成立数の集計（NF-08。#46）。成立の記録は残さない（利用者と決めた）
  - 監査ログ（#41）、D1 のバックアップ・外部サービスに残るデータ（#89）
  - 退避キューを読む処理（T-13 の手順書のとおり）

## 受け入れ条件
- [ ] 予定の時間の終わりから30日を過ぎた誘い・募集は、予定・参加者・宛先と一緒に、どの参加者の履歴からも消える。30日以内のものは残る
- [ ] 期限から30日を過ぎた招待リンクと、過去の日付のくり返しの例外が消える
- [ ] 有効なセッションがない人の連携は、定期の確認に割り当てられない。ログインし直すと、次の割り当てで確認が戻る
- [ ] 毎分の掃除の1つが失敗しても、ほかの掃除は走る。どの掃除もインデックスを使い、1回に消す数に上限がある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（対象なし。理由は仕様書）
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
