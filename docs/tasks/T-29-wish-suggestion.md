# T-29 行きたいのAI提案（エリアとしたいことから、店・場所の候補をURLつきで出す）

## 目的
行きたい（T-22）を置くとき、店やURLを自分で探す手間をなくす。エリアと「何をしたい？」を入れると、AIがWebを検索して候補を3件、選んだ理由とリンクつきで出す。気に入ったものを、今の置く画面に入れた状態で開く。置くかどうかは本人が決める。

## 関係する要件
- F-18（行きたいを置く）、F-15（リンクとOGPプレビュー）
- NF-05（ドメイン層は純粋）。外部の呼び出しは、本人がその場で待つ読み取りとして API から直接行う（T-06 決定事項11 と同じ扱い）
- 要求定義書「拡張のメモ（AI）」：カレンダーの情報はAIに渡さない、外部のAIのAPIを使うならプライバシー ポリシーに委託先として書く
- セキュリティ設計：ログに個人情報を出さない、外部APIの上限と利用料の急増への備え

## スコープ
- やること：
  - 行きたいの節に「AIで探す」を足し、エリアと「何をしたい？」を入れるシートを出す
  - 探すAPI：API のハンドラから Claude API（Haiku 5.5、Web検索のツールつき）を呼び、進み具合と候補をストリーミング（SSE）で返す
  - 候補を3件作る。入力の言葉と候補はサーバーに保存しない
  - 候補のURLは、Web検索の結果に出てきたものだけにする（AIが作ったURLは捨てる）
  - 候補から「行きたいに置く」で、今の置く画面をひとこと・リンク・エリアを入れた状態で開く
  - 1人1日の「探せる回数」（候補が出た回）と「試せる回数」（すべての回）の上限、サービス全体の1日の上限
  - プライバシー ポリシーの本文（実装PRで直す。T-19 の決まりで、効力の前に知らせる）
- やらないこと（スコープ外）：
  - 友達・ここ暇・カレンダー・今までの行きたいをAIに渡すこと、相手や日時の提案
  - 自動で行きたいを置くこと
  - 候補のカードの OGP の画像（置いたあとは T-08 のとおり出る）
  - 予約・アフィリエイトのリンク、店の検索の外部API（ホットペッパーなど）
  - 会話のやりとり（候補を見てから「もっと安く」と続けるなど）

## 受け入れ条件
- [ ] エリアと「何をしたい？」を入れて「候補を探す」を押すと、候補が3件まで、ひとことの案・選んだ理由・リンクつきで出る
- [ ] 候補のURLはすべて、その回のWeb検索の結果に出てきたURLである
- [ ] 「行きたいに置く」で、置く画面がひとこと・リンク・エリアを入れた状態で開く。置かなければ何も残らない
- [ ] 探している間は「Webで探しています」「候補を選んでいます」と進み具合が出る
- [ ] 見つからない・失敗したときは、赤を使わない静かな表示になり、探せる回数に数えない（試せる回数には数える）
- [ ] 1人1日の上限を超えると、探すボタンが押せず、その旨を静かに出す
- [ ] AIに渡るのは、入力したエリアと言葉だけ（友達・ここ暇・カレンダーの情報を渡さない）
- [ ] 入力した言葉・候補は、ログにも D1 にも残らない
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
