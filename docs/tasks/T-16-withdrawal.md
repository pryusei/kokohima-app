# T-16 退会

## 目的
利用者が自分で退会でき、本人のデータが消えるようにする。相手の履歴（誘い・募集・成立した予定・お知らせ）は消さずに残し、「退会したユーザー」と表示する。

## 関係する要件
- F-17：退会。本人のデータを削除。相手側の履歴は「退会したユーザー」と表示
- 要求定義書のイベント表「UserWithdrew」、データの最小化（保存するデータを減らす）
- issue：pryusei/kokohima-app#37（退会のタスク票がなく、今のスキーマは要件と逆の動きをする）

## スコープ
- やること：
  - 退会の API と画面（設定のアカウント）
  - 本人のデータの削除と、利用者の行を ID だけの「抜け殻」にすること
  - 進行中の誘い・募集・予定の後始末（「やっぱり難しい」と同じ扱い）と、Google カレンダーの連携の解除
  - 相手の画面での「退会したユーザー」の表示
  - 退会のあと、残っているアクセストークンで書き込めないこと
  - T-04〜T-07 の仕様書に散らばった退会の申し送りを、この仕様書に集める
- やらないこと（スコープ外）：
  - 退会の取り消し・猶予期間（すぐに消す。利用者と決めた）
  - D1 のバックアップ（Time Travel）・外部サービス（Resend・Google）に残るデータの扱い（#89）
  - 成立数の集計（NF-08。#46）と監査ログ（#41）。まだないので、作るときに退会を考える
  - アカウント連携（#45）

## 受け入れ条件
- [ ] 設定のアカウントから退会すると、その場でログアウトされ、同じ Google でまたログインすると新しい利用者になる
- [ ] 退会した人の名前・メール・ここ暇・友達・連携・お知らせ・書いたひとこと・エリア・リンクが残らない
- [ ] 相手の誘い・募集・予定・お知らせは残り、相手には「退会したユーザー」と出る
- [ ] これからの成立した予定は、退会した人が「やっぱり難しい」を押したのと同じになり、相手に知らせ、カレンダーから消える。返事待ちの誘い・募集は終わる
- [ ] 退会のあと、残っているアクセストークンで書き込めない
- [ ] 他人のIDでは退会させられない（自分の退会だけ）
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
