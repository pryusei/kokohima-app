# T-17 古いデータの掃除と保持期間

## 目的
終わった誘い・募集・予定、期限の過ぎた招待リンク、過去のくり返しの例外を、決めた期間のあとに毎分の掃除で消す。あわせて、表ごとの保持期間を一覧にする。30日アプリを開いていない人の連携では、カレンダーの確認を止める。

## 関係する要件
- 要求定義書「AI時代の攻撃を前提にした運用」：保存するデータを減らす
- NF-08（成立数などの集計）：今は記録を残さない（#46 で集計を作るときに決める）
- issue：pryusei/kokohima-app#38（古いデータの掃除と保持期間）の残り。済んだ分は T-12 データの増加（outbox・ここ暇）、#82（セッション）など

## スコープ
- やること：
  - 表ごとの保持期間の一覧（済んだものも参照として載せる）
  - 終わった誘い・募集・成立した予定を、終わってから30日で消す。お知らせも30日にそろえる（利用者と決めた）
  - 期限から30日を過ぎた招待リンク、過去の日付のくり返しの例外、流れないままの通知の記録、使えないセッションのプッシュの購読を消す
  - 友達を解除したら、公開設定の「見せる」の行を消す。「見せない」の行は退会まで残す（利用者と決めた）
  - 30日アプリを開いていない人（使える更新用トークンがなく、最後に使ってから30日を過ぎた人）の連携は休眠にし、カレンダーの定期の確認を止め、埋まりの記録を消す。ログインしたら記録だけから再開する（利用者と決めた）
- やらないこと（スコープ外）：
  - 成立数の集計（NF-08。#46）。成立の記録は残さない（利用者と決めた）
  - 監査ログ（#41）、D1 のバックアップ・外部サービスに残るデータ（#89）
  - 退避キューを読む処理（T-13 の手順書のとおり）

## 受け入れ条件
- [ ] 予定の時間の終わりから30日を過ぎた誘い・募集は、予定・参加者・宛先と一緒に、どの参加者の履歴からも消える。30日以内のものは残る
- [ ] お知らせは作ってから30日で消える
- [ ] 期限から30日を過ぎた招待リンク、過去の日付のくり返しの例外、流れないままの通知の記録（30日）が消える
- [ ] 友達を解除すると、両方向の公開設定の「見せる」の行が消え、「見せない」の行は残る（同じ招待リンクで戻っても見えないまま）
- [ ] 使えないセッションのプッシュの購読が消える
- [ ] 30日アプリを開いていない人の連携は休眠になり、埋まりの記録が消え、定期の確認に割り当てられず、休眠にする前の確認も記録を書かない。ログアウトしただけでは、すぐには休眠にならない。ログインし直すと戻り、次の確認は記録だけ（まとめての取り消しは起きない）
- [ ] 毎分・15分ごとの掃除の1つが失敗しても、ほかの掃除は走る。どの掃除もインデックスを使い、1回に処理する数に上限がある
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（対象なし。理由は仕様書）
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
