# T-21 行きたいリスト

## 目的
行きたい店やしたいことを、日時を決めずにリストとして置いておけるようにする。友達はそれを見て、その店でその人を誘える。相手が行きたがっているとわかっているので、誘う理由を考えなくて済み、誘う気まずさが減る。

## 関係する要件
- F-18〜F-21：行きたい（置く・見える相手・友達の行きたいから誘う・自分の行きたいから誘う／募集する）
- F-07：見せる／見せない（行きたいの見える相手にそのまま使う）
- F-10・F-11：個別の誘い・募集（作成画面に、行きたいの中身を入れた状態で開く）
- F-15：リンクとOGPプレビュー（行きたいのリンクにも使う）
- F-17：退会（行きたいも消す）
- NF-08：個人が特定されない集計

## スコープ
- やること：
  - 行きたいを置く・消す・一覧で見る（ひとこと必須、リンク1件とエリアは任意、期限なし、同時に10件まで）
  - 友達の行きたいの一覧（見える相手は、ここ暇の SharingPolicy をそのまま使う。見せない相手には、置いていないのと区別できない。友達でなくなったら見えない）
  - 友達の行きたいから、その友達への個別の誘いの作成画面を、ひとこと・リンク・エリアを入れた状態で開く
  - 自分の行きたいから、個別の誘いか募集の作成画面を、同じく入れた状態で開く（宛先は自分で選ぶ）
  - リンクの OGP カード（T-08 の `LinkAttached` とリンクの参照の対象に、行きたいを足す）
  - 退会での削除（T-16）と、保持期間の表への追加（T-17。「本人が消すまで」）
  - 仕様書の作成に合わせて、T-08・T-16・T-17 の仕様書と、invitation-domain スキルの用語表を直す（実装PRで）
- やらないこと（スコープ外）：
  - 「乗る」や反応、置いた人への知らせ（要求定義書「拡張のメモ」で見送り）
  - 行きたいを置いたときの友達への通知、週次通知
  - 行きたいと、そこから作った誘い・募集のつながりの保存（作成画面に中身を入れるだけ）
  - グループ単位の公開（Phase 2。公開範囲はあとで足せる形にだけしておく）
  - アフィリエイトリンク、AI による整理や推薦（要求定義書「拡張のメモ」）
  - 行きたいの編集（消して置き直すことで足りるかを仕様書で確かめる）

## 受け入れ条件
- [ ] 行きたいを置くと、自分の一覧と、見せている友達の一覧に出る
- [ ] 見せないにされている友達の一覧では、置いていないときと同じ形の応答になる（項目・件数・エラーで区別できない）
- [ ] 友達でない人・見せないにされている人が、行きたいの ID で取得すると、存在しない ID と同じ404になる。他人の行きたいは消せない
- [ ] 11件目を置こうとすると置けず、1件消すとまた置ける
- [ ] 友達の行きたいの「ここで誘う」から、宛先がその友達で、ひとこと・リンク・エリアが入った誘いの作成画面が開き、そのまま送れる
- [ ] 自分の行きたいの「誘う」「募集する」から、ひとこと・リンク・エリアが入った作成画面が開く
- [ ] リンク付きの行きたいに、OGP のカード（取れなければドメインだけ）が出る
- [ ] 退会すると、その人の行きたいが消える
- [ ] 他人のIDでは取得・更新できないテストがある（APIを追加する場合）
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（行きたいを置く → 友達がそれを見て「ここで誘う」 → 誘いを送る）
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る

## 仕様書
- docs/specs/T-21-wishlist.md（仕様書PRとして先に追加し、マージ後に実装PRを作る）
- 仕様書で決めること：コードの名前（Wish ほか）とコンテキストの置き場所（invitation の中か、availability と同じ支援の新しいコンテキストか）、API とデータ、作成画面に中身を渡す方法（URL のクエリか画面の状態か）、ひとことの長さの上限、一覧の並び順、友達の行きたいをどの画面に出すか
