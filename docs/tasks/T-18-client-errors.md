# T-18 画面（PWA）のエラーの収集

## 目的
画面で起きた例外（描画の失敗、捕まえていない例外、プッシュの購読や Service Worker の登録の失敗）を、個人情報を含めずに集め、T-13 のアラートで気づけるようにする。描画が壊れたときは、真っ白にせず静かな画面と「読み込み直す」を出す。

## 関係する要件
- 要求定義書「技術の選定」の監視、「AI時代の攻撃を前提にした運用」（異常のアラート）、「残りの論点」（異常検知）
- 要求定義書「AI時代の攻撃を前提にした運用」（保存するデータを減らす）：集めた内容は保存せず、ログ（7日）に出すだけ
- issue：pryusei/kokohima-app#88。関連：T-13（監視とアラート）、T-10（回数の上限）

## スコープ
- やること：
  - 受け口 `POST /api/v1/client-errors`（自前の API。ログに出すだけで保存しない。利用者と決めた）
  - ログインしていない画面のエラーも受ける（IP ごとの回数の上限と同じオリジンの確認で守る。利用者と決めた）
  - 画面の側の収集（捕まえていない例外、Promise の拒否、描画の例外、プッシュの購読と Service Worker の登録の失敗）
  - 描画が壊れたときの静かな画面と「読み込み直す」（利用者と決めた）
  - T-13 のアラートの一覧に `client_error` を足す
- やらないこと（スコープ外）：
  - 外部のエラー収集サービス（利用者と決めた）
  - 例外のメッセージ・スタックの収集、Service Worker の中のエラー、D1 への保存
  - 画面に問い合わせ番号を出すこと（T-13）

## 受け入れ条件
- [ ] 画面で捕まえていない例外・Promise の拒否・描画の例外・プッシュの購読の失敗・Service Worker の登録の失敗が起きると、受け口に送られ、`client_error` のログになる
- [ ] 送る内容は決めた値の一覧から選んだ項目（種類・例外の名前・ID を伏せた画面の経路・アプリのバージョン）だけで、メッセージ・スタック・URL の query とフラグメント・トークン・表示名は含まれない。ログにも IP・User-Agent・利用者 ID が出ない
- [ ] ログインしていなくても送れ、同じオリジンでない要求・回数の上限を超えた要求・本文が大きすぎる要求は受けない。上限を超えた要求はログも出さない
- [ ] `ApiError`（通信できないものを含む）・オフラインの間・通知の拒否では送らない（オフラインの間は1回・10件の枠も使わない）
- [ ] T-13 のアラートの一覧と手順書に `client_error` が入っている
- [ ] 他人のIDでは取得・更新できないテストがある（トークンを付けても、応答とログに利用者の ID もデータも出ない）
- [ ] 描画が壊れたとき、「うまく表示できませんでした」と「読み込み直す」が出る（赤を使わない）
- [ ] 同じエラーは1ページの間に1回、1ページで最大10件まで送る
- [ ] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（対象なし。理由は仕様書）
- [ ] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [ ] typecheck・lint・関係するテストが通る
