# T-35 仕様書：通知の見え方を本人が選ぶ

- 状態：実装済み
- タスク票：docs/tasks/T-35-notification-visibility.md
- 関係する要件：F-16 通知、NF-07、要求定義書「受容したリスク」（断りの気まずさ）。pryusei/kokohima-app#183（親 #178）
- 進め方：持ち主の決定で、仕様書と実装を同じ PR にする（1タスク2PRの例外）
- 改める仕様：docs/specs/T-07-notification.md（決定事項2「プッシュに中身を載せない」、「RFC 8291 の暗号化は実装しない」、Service Worker の決まった文）

## 概要
- 今のプッシュの本文は「新しいお知らせがあります」だけで、開く理由がない。断りもプッシュで送り手に届く。
- 体験の芯「嬉しい瞬間は鳴らし、気まずい瞬間は黙る」に合わせ、プッシュの本文を種類に応じた文にし、断り・見送り・取り消し・抜けたは鳴らさない。
- ロック画面に相手の名前と日時を出すかは本人が選ぶ（初期値は出さない）。中身を送るため、Web プッシュのペイロードの暗号化（RFC 8291、aes128gcm）を実装する。プッシュの事業者は中身を読めない。

## 決めたこと
持ち主の決定（1〜5）と、この仕様書で決めた細部（6〜）。

1. 見え方は2つ：「出さない」（`hidden`、初期値）と「名前と日時を出す」（`detailed`）。通知を許可するときに、ロック画面の見本を2つ並べて選ぶ。設定からいつでも変えられる。
2. 「出さない」でも種類は出す（「誘いが届きました」「募集が決まりました！」など）。
3. 「出す」でも、ひとこと・エリア・リンクは出さない。募集は決まる前に応答者の名前を出さない（応答はもともとお知らせにならない。決まった知らせに出すのは募集者の名前だけ）。
4. 断り（`invite_declined`）・見送り（`invite_skipped`）・予定の取り消し（`meetup_cancelled`）・予定から抜けた（`meetup_left`）は、どちらを選んでもプッシュもメールも送らない。お知らせ一覧にだけ残す。期限切れはもともとお知らせを作らない。
5. 暗号化は WebCrypto だけで実装する（`apps/api/src/notification/infra/`。`domain/` には入れない）。テストは RFC 8291 の付録 A の例で確かめる。
6. 夜のプッシュ：日本時間の22時〜翌7時は鳴らさず、メールにも切り替えず、お知らせ一覧にだけ残す（推奨で進めた。「確認事項」の1）。1日の上限は今のまま（推奨。「確認事項」の2）。
7. 日時は開始の時刻だけ（例：「11月28日(土) 19:00〜」）。受け取り手のタイムゾーンで出す。「この時間なら」は代わりの時間を出す。
8. メールの中身は変えない（種類の短い説明だけ。T-07 決定事項6）。見え方の設定はプッシュだけに効く。
9. 暗号化する前の本文は1024バイトにそろえる（詰め物）。プッシュの事業者に、暗号文の長さから種類や名前の長さを推し量らせない。
10. 鍵のない購読（T-35 より前に登録したもの）には、今までどおり本文なしで送り、Service Worker は決まった文を出す。アプリを開くと購読を送り直すので（T-07）、そのときに鍵が付く。

| 画面 | コード | 備考 |

| 鳴らさない知らせ | `SILENT_KINDS` | 断り・見送り・取り消し・抜けた。プッシュもメールも送らない |

## API
`api-conventions` スキルに従う。新しいエンドポイントはない。T-07 のものの入出力を変える（スキーマは `packages/shared/src/schemas/notification.ts`）。

| メソッド | パス | 変えること |
| --- | --- | --- |
| GET・PATCH | `/api/v1/me/notification-preferences` | `notificationPreferencesSchema` に `lockScreen`（`"hidden"`／`"detailed"`）を足す。行がなければ `"hidden"`。PATCH は今までどおり1項目以上（strict）。知らない値は400 |
| POST | `/api/v1/push/subscriptions` | `pushSubscriptionRequestSchema` に任意の `keys: { p256dh, auth }`（base64url。p256dh は65バイトで先頭が `0x04`、auth は16バイト。strict）を足す。形が違えば400 |
| DELETE | `/api/v1/push/subscriptions` | `pushUnsubscribeRequestSchema`（`{ endpoint }` だけ。strict）。鍵は受け取らない |

## データ
マイグレーション `apps/api/migrations/0020_notification_visibility.sql`。
- `notification_preferences.lock_screen`（TEXT、NOT NULL、既定 `'hidden'`）。知らない値は `hidden` として読む。
- `push_subscriptions.keys_enc`（TEXT、null 可）。`{ p256dh, auth }` の JSON を T-06 の `encryptSecret` で暗号化する（鍵は `NOTIFICATION_KEYS`、AAD は `push-keys:<user_id>`。endpoint の AAD `push:<user_id>` とは別）。
  - 同じ endpoint の登録し直し（付け替えを含む）は、そのときの鍵に置き換える。鍵のない登録では null にする。
  - 消すときは購読の行ごと消える（ログアウト・届けられない・セッションの失効・退会。T-07・T-16・T-17 のまま）。
- `notifications.outcome` に `silent`（鳴らさない知らせ）と `night`（夜で鳴らさなかった）を足す（列は TEXT のまま）。

## 振る舞い

### 届ける（T-07「届ける」の手順を改める）
1. 鳴らさない知らせなら、送らずに `channel = 'none'`・`outcome = 'silent'` を書く（止める設定・上限より先に見る）。
2. 止めた種別は今までどおり `muted`。
3. プッシュの購読があるとき
   - 夜（日本時間の22:00〜6:59）なら、送らずに `channel = 'none'`・`outcome = 'night'` を書く。メールに切り替えない。1日の数にも数えない。
   - 1日の上限は今までどおり。
   - 中身を作り、購読ごとにその購読の鍵で暗号化して送る（下の「暗号化」）。鍵がない・読めない購読には本文なしで送る（ログは `notification_push_plain`、種類と理由だけ）。
4. 購読がない人へのメールは、夜でも送る（今までどおり。止めるのはプッシュだけ）。
- 夜の判定は E2E のエントリだけで外せる（`AppDeps.notification.quietHours`。本番は `true`、E2E は `false`。CI がいつ走ってもプッシュの流れを確かめるため。判定は単体テストで確かめる）。
- 日本時間に夏時間はないので、UTC に9時間を足した時で決める。

### プッシュの本文
- Service Worker に渡す中身は JSON `{ v: 1, id, body }`。`id` はお知らせの ID（同じお知らせの再送を1つにまとめる `tag` に使う）。
- `body` は種類に応じた文。`detailed` では、相手の名前と開始の日時を足す（2行め）。

| 種類 | 出さない | 名前と日時を出す |
| --- | --- | --- |
| `invite_received` | 誘いが届きました | 〇〇さんから誘いが届きました／日時 |
| `invite_countered` | 別の時間の提案があります | 〇〇さんから別の時間の提案があります／代わりの時間 |
| `broadcast_received` | 募集が届きました | 〇〇さんが募集しています／日時 |
| `broadcast_decided` | 募集が決まりました！ | 〇〇さんの募集が決まりました！／日時 |
| `meetup_confirmed` | 予定が成立しました！ | 〇〇さんと予定が成立しました！／日時 |
| `friend_added` | 友達が増えました | 〇〇さんと友達になりました |
| `availability_cancelled` | カレンダーの予定と重なったここ暇を〇件取り消しました | 同じ |
| `calendar_reauth` | カレンダーの連携が切れました | 同じ |

- 鳴らさない知らせと `new_login`（メールだけ）はプッシュにしないので、文を持たない。
- 名前はお知らせ一覧と同じく、受け取り手を閲覧者として `getHistoryProfiles` で読む。表示名がなければ「名前未設定の友達さん」、退会した人は「退会したユーザー」（さんを付けない）。読めなければ名前のない文。
- 日時は invitation の `slotStartOf`（consumer 用。閲覧者で絞らない。受け取り手が決まったお知らせの対象の ID だけを渡す）で、誘い・代わりの時間・募集・予定の開始を読む。なければ1行めだけ。
- 詰め物の長さに入らなければ、種類だけの文にする。

### 暗号化（`infra/webpush-encryption.ts`）
- RFC 8291 と RFC 8188 の aes128gcm。WebCrypto の ECDH（P-256）・HKDF（SHA-256）・AES-128-GCM だけを使う。
- 送るたびに一時的な鍵の組と16バイトの salt を作る。レコードの大きさ（rs）は4096、レコードは1つ。
- 本文 || `0x02` || `0x00` の詰め物で1024バイトにそろえる。送る本文は86＋1024＋16＝1126バイトで、いつも同じ。
- ヘッダー：`Content-Encoding: aes128gcm`、`Content-Type: application/octet-stream`、`TTL`・`Urgency`・`Authorization: vapid`（T-07 のまま）。本文なしのときは今までどおり `Content-Length: 0`。
- 鍵・本文はログに出さない。

### Service Worker（`apps/web/public/sw.js`）
- `push` で中身を読み、`v` が1で `body` が空でない文字列なら、`showNotification("ここ暇", { body: 先頭200字, tag: "kokohima-<id>" })`。
- 中身がない・読めない・形が違うときは、今までどおり `{ body: "新しいお知らせがあります", tag: "kokohima" }`。
- `notificationclick` はお知らせ一覧（`/notifications`）を開く（T-07 のまま）。API は呼ばず、キャッシュもしない。

### 画面
- 部品 `LockScreenPicker`（`apps/web/src/notifications/LockScreenPicker.tsx`）：見出し（`legend`）「ロック画面に出す中身」、ラジオの2択を見本のロック画面（時刻と、ここ暇の通知の吹き出し）と並べる。
  - 「出さない」の見本：「誘いが届きました」。「名前と日時を出す」の見本：「ゆいさんから誘いが届きました」「11月28日(土) 19:00〜」。
  - 選んだ枠は lamp の輪（`border-lamp-line`・`shadow-lamp`）。赤・エラー色は使わない。トークンだけを使う。
  - 選ぶとすぐ PATCH する（楽観的に変え、失敗したら戻して「変更できませんでした。もう一度お試しください」）。オフラインの間は選べない。
  - 下に1行「どちらでも、ひとこと・場所・リンクは出ません」。
- 友達になった直後の画面（T-31）：プッシュを受け取れる端末で、まだ受け取っていないとき、「お知らせを受け取る」の上に置く（許可はボタンを押したときに求める）。この画面は説明を1行に抑えるので、下の1行は出さない。
- 通知の設定（`/settings/notifications`）：節「ロック画面」に置く。下に1行「断り・見送り・取り消しと、夜22時〜朝7時は鳴らさず、お知らせ一覧にだけ残します」。
- 購読の登録と送り直しでは、`subscription.toJSON().keys` の `p256dh`・`auth` を endpoint と一緒に送る。解除は endpoint だけ。

### プライバシー ポリシー（T-19「9.」）
- 保存する情報（通知の設定の見え方・購読の鍵）と外に渡すもの（プッシュの事業者に暗号化した中身）が変わるので、同じ PR で直す。本格稼働までは予告なし（T-19 決めたこと17）。
- 本文の「2.」通知のためのもの：設定にロック画面の見え方、プッシュの宛先と暗号化の鍵（暗号化して保存）。
- 「5.」と「7.」のプッシュの事業者：渡すのは宛先と、事業者が読めないように暗号化した中身。中身は種類で、選んだときだけ相手の表示名と予定の日時。ひとこと・エリア・リンクは入れない。
- 「8.」：プッシュの宛先と暗号化の鍵を消すとき。安全の措置：宛先と鍵は暗号化して保存。
- 日付：`apps/web/src/pages/legal.ts` の改定日をマージしてデプロイする日（今は「2026年11月24日」）にし、`REVISION_NOTICE_LINE` と `*_REVISION_CHANGES` は `null` のまま。マージの日がずれたら改定日を同じ日にする。

## 認可と秘匿
- 閲覧者IDの使い方：設定と購読は今までどおり `user_id = 閲覧者` でだけ読み書きする。届ける処理は、お知らせの `user_id`（受け取り手）の設定と購読の鍵だけを使う。
- 他人のデータに届かないことの保証：
  - 名前は受け取り手を閲覧者として読む（お知らせ一覧で見えるものと同じ）。日時は受け取り手あてのお知らせの対象だけを読む。
  - 購読ごとにその購読の鍵で暗号化するので、ほかの人の端末では読めない。鍵の AAD に利用者の ID を入れ、別の人の行の鍵として復号できない。
  - 受け入れること（T-07 のまま）：endpoint を知っている人は他人の購読を自分に付け替えられる。付け替えると鍵も付け替えた人のものに替わり、元の人の端末では読めない（決まった文が出る）。
- 区別させない応答：
  - 鳴らさない知らせは、自動の「今回は難しい」（T-06）と手の断りで同じ（どちらも `invite_declined`）。断りは送り手のロック画面に出ないので、見せない相手・暇がない相手の区別は今までと変わらない。
  - 募集の応答はお知らせにならない（T-07）。決まった知らせの名前は募集者だけ。
  - 暗号文の長さはいつも同じ。
- 外に渡すもの：プッシュの事業者には、宛先・VAPID の署名・暗号化した中身（事業者は読めない）。ログには、種類・送り先の種類・結果・状態コード・理由だけ。

## スコープ外
- メールの中身を見え方に合わせること（決めたこと8）。
- お知らせを押して対象の画面へ直接開くこと（今までどおりお知らせ一覧を開く）。

- 1日の上限の見直し。

## 確認事項（持ち主の判断。返事がなければ推奨のとおり）
1. 夜のプッシュ：22時〜7時（日本時間）は鳴らさず、お知らせ一覧にだけ残す。推奨：このまま（実装済み）。ほかの案：夜も鳴らす／夜の分を朝7時にまとめて鳴らす。
2. 1日の上限を3件にするか。推奨：入れない（今の30件のまま）。ほかの案：誘い・募集・友達のプッシュを3件に。
3. 予定から抜けた（`meetup_left`）も鳴らさない知らせに入れた。推奨：このまま（抜けた側の気まずさを残りの人の端末で鳴らさない）。ほかの案：鳴らす。
