# T-46 仕様書：「この時間なら」のカードの崩れとフォーカスの輪

- 状態：実装済み
- タスク票：issue pryusei/kokohima-app#194（親 #178）
- 関係する要件：F-12（返答。この時間なら）、要求定義書「デザイン原則」、アクセシビリティ（フォーカス。WCAG 2.4.7）。docs/specs/T-04-direct-invite.md「画面」、docs/specs/T-11-design.md「デザインの決まり」「共通の部品」

## 概要
- 2026-11-23 の UI のレビュー（観点4）で「高」とした2つを直す。
  1. 「この時間なら」が返ってきた送信の誘いのカードが崩れる。バッジ（`shrink-0`）に「この時間なら：10/10（土） 13:00〜15:00」と長い文言が入り、宛先の名前の幅が0になって「ここどう？」が1文字ずつ縦に並び、バッジがカードの右端からはみ出す（幅390pxで、バッジの右端377px、カードの右端374px）。さらに、大きく出ている時刻は元の時刻で、「決める」で決まる代わりの時刻はバッジの中にしかなく、決める時刻を取り違えるおそれがある。
  2. フォーカスの輪が出ない部品がある。`index.css` の `:focus-visible` は `outline: none` と `box-shadow` で輪を描いているが、`shadow-card` などの影のクラスが `box-shadow` を上書きする（誘い・募集のカード、誘いタブの区切り、友達タブの「設定」）。強制カラーのモードでは `box-shadow` が描かれず、輪がまったく出ない。
- 見た目だけを直す。API・データ・認可は変えない。

## API

## データ
変えない（マイグレーションなし）。

## 振る舞い

### 1. 「この時間なら」が返った送信の誘い（`direction = sent`、`status = counter_proposed`）
- 状態の文言（`statusText`）は「この時間なら」だけにする（前は「この時間なら：10/10（土） 20:00〜23:00」）。バッジの色は今のまま `lamp`。受信者の「この時間ならと返しました」は変えない。
- 大きく出す時間は、代わりの時間（`counterProposal`。「決める」で決まる時間）にする。その下に、元の時間を小さく（`text-s`・`text-ink-muted`）「最初の時間 15:00〜17:00」と添える。
  - 元の時間が代わりの時間と同じ日（Asia/Tokyo）なら時刻だけ、別の日なら日付も添える（「最初の時間 10/10（土） 15:00〜17:00」）。
  - 誘いタブの送信の一覧のカード（`InviteCard`）と、誘いの詳細（`/invites/{id}`）の両方で同じにする。表示の関数は `apps/web/src/invitations/format.ts` の `inviteTimes` の1か所に置く。
- 誘いの詳細の「決める」のボタンに、代わりの時間の開始の時刻を入れる：「13:00〜で決める」（`decideLabel`）。「見送る」は変えない。
- それ以外の状態・受信者の誘いは、今のまま誘いの時間だけを大きく出す（小さい行は出さない）。
- 誘い・募集のカードの見出しの2行め（「あそぼ」「ここどう？」など）も、名前と同じく1行で切り詰める（`truncate`）。バッジに押されても縦に並ばないようにする。

### 2. フォーカスの輪
- `index.css` の `@layer base` の `:focus-visible` を、`outline: 2px solid var(--color-focus); outline-offset: 2px;` にする。`box-shadow` は使わない。
  - `outline` は影のクラス（`shadow-card` など）と別の性質なので、上書きされない。強制カラーのモードでも描かれる。
  - 前の「`surface` の2pxの隙間」は、`outline-offset: 2px` の透明な隙間に置き換える（下の面の色が見える）。
- `Switch` は、透明に重ねたチェックボックスの代わりにつまみの面に輪を出す。この輪も `box-shadow` から `outline`（`peer-focus-visible:outline-2`・`outline-offset-2`・`outline-focus`）に変える。
- ソースで輪を消す指定（`outline-none`・`outline-hidden`・`outline-0`、フォーカスのときの `shadow-` の指定）を使わない。単体テストでソースを検査する。

## 認可と秘匿
- 閲覧者IDの使い方：変えない（API を変えないため）。
- 他人のデータに届かないことの保証：変えない。代わりの時間は、今も詳細と一覧の応答に入っている `counterProposal` を表示するだけ。
- 区別させない応答：変えない。受信者の表示は変えず、断り・期限切れ・見送りの文言と色も今のまま。

## テスト計画

### 単体テスト（実装PRで必須）
- [x] `statusText`：送信者の `counter_proposed` は「この時間なら」だけ。受信者は「この時間ならと返しました」。
- [x] `inviteTimes`：送信者の `counter_proposed` は、代わりの時間を `when`、「最初の時間 15:00〜17:00」を `original` にする。別の日なら `original` に日付も添える。受信者・ほかの状態は誘いの時間だけで、`original` は null。
- [x] `decideLabel`：「13:00〜で決める」。
- [x] 誘いの詳細：送信者の `counter_proposed` で、バッジ「この時間なら」、代わりの時間、「最初の時間 …」、「20:00〜で決める」のボタンが出る。
- [x] 誘いタブの送信の一覧：`counter_proposed` のカードで、バッジは「この時間なら」だけ（`lamp`）、代わりの時間と「最初の時間 …」が出て、宛先の名前と「ここどう？」が `truncate` で1行になる。
- [x] フォーカスの輪：`index.css` の `:focus-visible` が `outline: 2px solid var(--color-focus)` と `outline-offset: 2px` で、`outline: none`・`box-shadow` を含まない。ソースに輪を消す指定がない（検査が見つけられることも確かめる）。
- [x] 他人のIDでは取得・更新できない：API を変えないので、新しいテストはない。既存のテストが通る。

### E2Eテスト（対象にする利用者の流れ）
- [x] 既存の「AがCに、ここ暇がない時間で誘う（ここどう？）→ Cが『この時間なら』→ Aが『決める』→ 双方に成立」（`e2e/invites.spec.ts`。`mobile` の幅390px）を直す：
  - Aの詳細に、バッジ「この時間なら」、代わりの時間（13:00〜15:00）、「最初の時間 10:00〜12:00」が出る。
  - Aの送信の一覧のカードで、バッジの右端がカードの右端を越えず、宛先の名前に幅がある（崩れがない）。
  - 誘いタブの「成立」のタブから Tab を押すとカードにフォーカスが着き、`outline` が実線の2pxになる。
  - 「13:00〜で決める」を押して成立する。
- WebKit（`@iphone`）では回さない。見た目の検査は Chromium の `mobile` で足りる（T-21 の決まりのとおり、印は付けない）。

## スコープ外
- 受信者の「この時間ならと返しました」のときに代わりの時間を出すこと。
- 募集のカード・ほかの画面のバッジの文言。
- `Badge` の部品そのもの（`shrink-0` のまま）。長い文言を入れないことで直す。
- 強制カラーのモードでの、ほかの見た目（影・面の色）の調整。
