# T-31 表示名を最初のログインで必須にし、友達になった直後の1画面を出す

## 目的
表示名が空のまま友達になる人をなくし、友達追加の通知から「誰と友達になったか」がわかるようにする。友達になった直後に、ここ暇を1つ出すこととお知らせを受け取ることを、飛ばせる形で案内する。

## 関係する要件
- F-01（認証）、F-08（友達追加：発行者の表示名を見て「友達になる」を1回押す）
- 要求定義書の受容したリスク「友達追加の通知からの公開オフ」、未決事項「表示名・アイコン・プロフィール項目」
- issue：pryusei/kokohima-app#179（親 #178）
- T-15（docs/specs/T-15-onboarding.md）の表示名の必須化と最初の流れを置き換える

## スコープ
- やること：
  - 表示名が空の人に、どの画面の代わりにも名前の画面を出す（新しい利用者も、既存の空の人も）
  - 招待の受け口で、名前の入力を「友達になる」の確かめと1つの画面にする（1つの欄と「これで友達になる」）
  - 表示名が空の人の `accept` を409にする（サーバーで保証する）
  - 友達になった直後の1画面（`/welcome`）：「ここ暇を1つ出す」（プリセットのチップ）と「お知らせを受け取る」。どちらも飛ばせる
  - 説明の文は1画面1行まで
  - T-02・T-15 の仕様書、T-15 のタスク票、要求定義書、画面の一覧を合わせる
- やらないこと（スコープ外）：
  - LINE の名前を表示名の下書きに入れること（LINE ログインがまだない）
  - アイコンの初回設定、カレンダー連携の案内（最初の流れから外す）
  - 設定のアカウントの通知の宛先（`emailHint`。T-15 に残す）

## 受け入れ条件
- [x] 表示名が空の利用者が新しく友達にならない（`accept` が409。既存の空の人は、次に開いたときに名前の画面で入れる）
- [x] 招待を開く → 名前 → 友達 → 直後の画面、の流れで、名前を入れて1回押すと友達になる
- [x] 直後の画面で、ここ暇を1つ出せ、お知らせを受け取れ、どちらもしないで友達タブへ進める
- [x] 他人のIDでは取得・更新できないテストがある（新しい経路はなく、T-02 のテストのまま）
- [x] 単体テストが追加され、通る
- [ ] 仕様書でE2Eの対象にした流れのE2Eテストが通る（CI で確かめる）
- [x] 仕様書とコードに齟齬がない（仕様の変更は仕様書に反映済み）
- [x] typecheck・lint・関係するテストが通る
